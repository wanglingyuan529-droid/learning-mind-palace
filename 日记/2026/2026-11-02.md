# 2026-11-02 学习日记

> 接着昨天的 Map 往下走。昨天是「Map 是什么、怎么遍历」，今天是**三个实现类各自的特性和边界**。

## 🎯 今天一句话

**三个 Map 的差别落到两件事上：要不要顺序、允不允许 null —— 而 TreeMap 的 null 限制不是设计小气，是它必须比大小。**

## ✅ 学到了什么

### Java · HashMap 的 null 特性（今天新知道的）

| 能不能放 | HashMap |
| --- | --- |
| `null` 键 | ✅ 允许，**但只能有一个** |
| `null` 值 | ✅ 允许，要几个都行 |

为什么能放 null 键：HashMap 靠哈希定位，而 `null` 的哈希值被规定为 0，所以它就固定待在数组下标 0 的位置。这不是"特殊照顾"，是哈希规则自然容纳了它。

### Java · LinkedHashMap

- 和 HashMap 的唯一区别：**多了保序**，按元素**放进去的顺序**输出。
- 其他完全一样（包括允许 null 键值）。
- 底层在哈希表之外多挂了一条双向链表，把插入顺序串起来。所以内存稍大、速度略慢，但差异很小。

### Java · TreeMap

- 特点：**按键排序**，而且**只对键排序，不对值排序**。
- 顺序和"放进去的顺序"无关，是**排序后的顺序**——这点和 LinkedHashMap 的「保序」不是一回事，容易混：

| | 顺序从哪来 |
| --- | --- |
| LinkedHashMap | 你**放进去**的顺序 |
| TreeMap | 按**比较规则**排出来的顺序 |

**按 key 排序**：天然就有（key 实现 Comparable，或创建时传 Comparator）。

**按 value 排序**（今天的重点练习）：TreeMap 本身做不到，得绕一圈——

```java
// ① 把键值对拆出来放进 List
List<Map.Entry<String, Integer>> list = new ArrayList<>(map.entrySet());

// ② 写比较器，按 value 比较
list.sort((a, b) -> b.getValue() - a.getValue());   // 降序

// ③ 排完再遍历
for (Map.Entry<String, Integer> e : list) {
    System.out.println(e.getKey() + "=" + e.getValue());
}
```

记一句话：**Map 只有"按键排序"的能力，要按值排就得先转成 List 再 sort。**

### Java · TreeMap vs TreeSet（把昨天的接上了）

昨天学的这个区别，今天自己复述出来了：

| | `compareTo` / `compare` 返回 0 时 |
| --- | --- |
| **TreeSet** | 认为是重复，**丢弃**新元素 |
| **TreeMap** | 认为是同一个 key，**覆盖** value |

原因：Set 只有元素本身，重复了没地方放；Map 有 value，键重复时 value 还有替换的余地。

> 所以要特别注意：**TreeMap 里比较器写错了，数据不会"丢"，而是被静默覆盖** —— 比丢更难发现。
> 顺带补一条昨天没说的：**TreeMap 不允许 null 键**（排序时拿 null 去比较会抛 `NullPointerException`）。

## 🔍 自测（先遮住答案）

> [!question]- Q1：三个 Map 里，哪个不允许 null 键？为什么？
> **TreeMap 不允许**。
> 因为 TreeMap 靠 `compareTo` / `compare` 排序，`null` 没法参与比较，一放进去就抛 `NullPointerException`。
> 而 HashMap 靠哈希定位，`null` 的哈希被规定成 0，所以能放（而且只能放一个）。
> LinkedHashMap 继承 HashMap，null 规则一致。

> [!question]- Q2：LinkedHashMap 的「保序」和 TreeMap 的「有序」，是同一个意思吗？
> 不是。
> - **LinkedHashMap 保的是插入顺序**：先放 A 后放 B，输出就是 A、B。
> - **TreeMap 排的是比较顺序**：先放 B 后放 A，如果 A < B，输出还是 A、B。
>
> 一个是"记住你放的顺序"，一个是"按规则重新排"。需求说"按放进去的顺序"用前者，说"按大小/字典序"用后者。

> [!question]- Q3：按 value 给 TreeMap 排序，为什么不能直接排？
> 因为 TreeMap 的整棵红黑树是**按 key 组织**的，排序规则作用在 key 上，value 只是挂在上面的数据。
> 要按 value 排，必须先跳出 Map —— 用 `entrySet()` 把键值对搬到 `List` 里，再对 List 用 `sort`。
> 这也是为什么"按值排序"在 Map 里是个绕路操作。

## 📎 补充：几个今天值得记住的

> [!note] 1. `wraparound` 是个真会咬人的坑
> `int` 最大值 2147483647 再加 1，会变成 -2147483648，**不会报错**，就这么绕回去了。
> 这叫整数溢出回绕。所以在 Java 里算钱、算字节数、算计数，超过 21 亿就该考虑 `long` 了。

> [!note] 2. emulation 和 simulation 不是一回事
> - **emulation**：模仿**内部实现**，让 A 表现得和 B 一模一样（比如模拟器运行另一个系统的程序）；
> - **simulation**：模仿**外部行为**，用来研究、预测（比如天气模拟、负载模拟）。
>
> 技术上区分很明确，日常说话经常混用。

> [!note] 3. `adapter` 不只是电源头
> 编程里 **适配器模式**：把一个类的接口转成调用方期望的另一种接口。
> 常见例子：`InputStreamReader` 把字节流转成字符流，就是 adapter。
