# 2026-11-01 学习日记

> 集合框架最后一块拼图：Map。学完这篇，List / Set / Map 三块齐了。

## 🎯 今天一句话

**单列集合一次存一个元素，双列集合一次存一对——而 `put` 有返回值这件事，是 Map 里最容易被忽略、也最好用的设计。**

## ✅ 学到了什么

### Java · 单列 vs 双列

| | 单列集合 | 双列集合（Map） |
| --- | --- | --- |
| 一次存 | 一个元素 | 一对：键 + 值 |
| 类比 | 一排格子 | 字典（查词 → 释义） |
| 代表 | `List` / `Set` | `Map` |

### Java · Map 的三个基本特点

1. **一个键对一个值**：`Map<K, V>`。
2. **键唯一，值可重复**：同一个键再 put，不会多出一条，而是把旧值换掉。
3. **键和值都必须是对象**：不能写 `Map<int, int>`，要 `Map<Integer, Integer>`。

**一个键想对多个值怎么办**：值换成集合 —— `Map<String, List<Integer>>`。这是实际开发里很常用的结构。

### Java · 三个实现类怎么选

| 实现类 | 顺序 | 查找 | 什么时候用 |
| --- | --- | --- | --- |
| **HashMap** | 无序 | 最快（平均 O(1)） | **默认选它**，99% 的场景 |
| **LinkedHashMap** | 保持**插入顺序** | 一样快 | 要按放进去的顺序输出 |
| **TreeMap** | 按 **key 排序** | O(log n) | 需要按 key 有序遍历 |

记住一个判断顺序：**先想「要不要顺序」，再想「哪种顺序」**。都要不了就 HashMap。

### Java · 重点：`put` 的返回值

```java
V put(K key, V value)   // 返回这个键原来的旧值；没有旧值就返回 null
```

看着不起眼，但它直接支撑两个常见需求：

| 用途 | 写法 |
| --- | --- |
| **判断是不是第一次放入** | `if (map.put(k, 1) == null) { /* 首次 */ }` |
| **统计词频** | `map.put(w, map.getOrDefault(w, 0) + 1)` |

**坑**：如果之前真的存过一个 `null` 值，`put` 也返回 `null`，两种情况分不开。这时要用 `containsKey(key)` 才能确定。

### Java · 三种遍历方式

```java
// ① keySet：先拿所有键，再用键去 get 值
for (String k : map.keySet()) { Integer v = map.get(k); }

// ② entrySet：一次性拿到"键值对对象"
for (Map.Entry<String, Integer> e : map.entrySet()) {
    String k = e.getKey();  Integer v = e.getValue();
}

// ③ forEach + lambda：最简洁
map.forEach((k, v) -> System.out.println(k + "=" + v));
```

**怎么选**（今天自己总结的）：

| 场景 | 用哪个 | 理由 |
| --- | --- | --- |
| 只要键 | `keySet` | 不用取值 |
| 要键也要值，且数据量大 | `entrySet` | 拿节点时值已经在手里 |
| 日常输出 / 简单处理 | `forEach` | **首选**，最简洁 |

**为什么 `keySet` + `get` 慢**：每 `get(key)` 一次，都要重新算一次哈希、再查一次表；而 `entrySet` 遍历时，键和值是从同一个节点里直接取的，不用二次查找。数据量小时差别看不出来，几十万条就明显了。

## 🔍 自测（先遮住答案）

> [!question]- Q1：`map.put("a", 1)` 第二次执行 `map.put("a", 2)` 时，返回值是什么？map 里有几条数据？
> 返回 `1`（旧的 value）。map 里仍然只有 **1 条**数据，只是 value 变成了 2。
> key 唯一，再 put 是"覆盖 value"，不是"新增一条"。

> [!question]- Q2：既然 `forEach` 最简洁，为什么还要学 `entrySet`？
> 因为 `forEach` 本质就是 `entrySet` 遍历的语法糖，性能是同一档。
> 而 `keySet` + `get` 是**真的慢**——每次 get 都要二次查找。
> 说"forEach 日常首选"，是因为它既简洁又不失性能；`entrySet` 在需要精细控制（比如中途 `break`、要 `remove`）时更合适。

> [!question]- Q3：TreeMap 和 TreeSet 遇到 `compareTo` 返回 0，行为一样吗？
> **不一样，这是个容易错的点。**
> - **TreeSet**：认为"重复"，直接把新元素**丢弃**。
> - **TreeMap**：认为"是同一个 key"，用新 value **覆盖**旧 value。
>
> 原因：Set 只有元素本身，重复了就没得放；Map 有 value，键重复时 value 还有替换的余地。
> 所以在 TreeMap 里比较器写错，数据不会"丢"，而是被**静默覆盖**——这个更难发现。

## 📎 补充：几个原文没提但值得记住的

> [!note] 1. O(1) 是"平均"，不是"永远"
> HashMap 的 O(1) 是**哈希均匀时的平均情况**。冲突严重时会退化。
> Java 8 之后：链表长度 ≥ 8 **且** 数组容量 ≥ 64 时，链表转成红黑树，最坏也能保持 O(log n)。
> 所以"查找最快"指正常情况，加了红黑树是**兜底**。

> [!note] 2. 用自定义对象当 key，必须重写 hashCode + equals
> 这就是 10-31 学的那套：hashCode 找桶、equals 精确比。
> 没重写的话，两个"内容相同"的对象算出的哈希不同，落到不同桶，`get` 就查不到（返回 null），
> `put` 还会悄悄存成两条 —— 表现得像"数据丢了"，其实是一直在错地方找。

> [!note] 3. TreeMap 的 key 必须"能比较"
> 不像 HashMap 什么都能放，TreeMap 的 key 必须实现 `Comparable`，或者在创建时传 `Comparator`。
> 否则放**第二个**元素时抛 `ClassCastException`（和 TreeSet 一样，第一个不报错）。
