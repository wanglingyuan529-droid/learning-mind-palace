# 2026-11-09 学习日记

> 今天一整块：Stream 流。这条线在集合之后就顺下来了——集合负责"存"，Stream 负责"算"。

## 🎯 今天一句话

**Stream 的惰性求值不是偷懒，是设计：没有终结方法，前面写的所有中间操作一行都不会跑。**

## ✅ 学到了什么

### Java · Stream 的三条铁律

| 铁律 | 什么意思 | 后果 |
| --- | --- | --- |
| **不修改原数据** | Stream 是对源集合的"视图 + 加工"，不动原件 | 想让原集合变，得自己接住返回值 |
| **只能消费一次** | 一条流走完就废了 | 第二次用抛 `IllegalStateException` |
| **惰性求值** | 中间方法只登记，不执行 | 没有终结方法 → 什么都别想发生 |

第三条最容易踩。写一长串 `filter().map().sorted()` 却没调用 `collect()`，程序会**安静地什么都不做**，不报错，就是没结果。

### Java · 中间方法 vs 终结方法

**中间方法**：返回一个新的 Stream，所以能一直链下去。

| 方法 | 干什么 |
| --- | --- |
| `filter` | 筛 |
| `map` | 转换（一变一） |
| `flatMap` | 转换（一变多，把嵌套拍平） |
| `sorted` | 排序 |
| `limit` / `skip` | 截取 |
| `distinct` | 去重 |

**终结方法**：返回一个具体结果，**流到这里就结束**。

`collect` / `forEach` / `count` / `reduce` / `anyMatch` / `findFirst` / `toArray`

判断口诀：**返回 `Stream` 的是中间，返回"别的东西"的是终结。**

### Java · 今天踩的五个坑

| # | 坑 | 现象 / 原因 |
| --- | --- | --- |
| 1 | 流只能消费一次 | 复用同一个 Stream 变量 → `IllegalStateException` |
| 2 | 没有终结方法就不执行 | 惰性求值，不报错但没结果 |
| 3 | `toMap` 的 key 重复 | 抛 `IllegalStateException: Duplicate key` |
| 4 | `.toList()` ≠ `Collectors.toList()` | 前者**不可变**，后者**可变** |
| 5 | jshell 里流式必须写成一行 | jshell 逐行执行，链式换行会被当成多条语句 |

**第 4 条说清楚**：

```java
// 不可变（JDK 16+）：返回的列表不能再 add/remove
List<String> a = stream.toList();

// 可变：返回 ArrayList，能继续改
List<String> b = stream.collect(Collectors.toList());
```

两个名字看着像兄弟，行为完全不同。要不可变又用 collect，得写 `Collectors.toUnmodifiableList()`。

**第 5 条有个绕法**（见补充 2）。

## 🔍 自测（先遮住答案）

> [!question]- Q1：写了一段 `list.stream().filter(x -> x > 3).map(x -> x * 2);` 什么都没输出，为什么？
> 因为**没有终结方法**。Stream 是惰性的——`filter` 和 `map` 只是把"要做什么"登记下来，一条流水线画好了但没开机。
> 加上 `collect(...)`、`forEach(...)`、`count()` 之类的终结方法，它才会真正跑。
> 这个坑不报错，只是"静默无效果"，最难查。

> [!question]- Q2：`.toList()` 和 `Collectors.toList()` 有什么区别？
> - `stream.toList()`（JDK 16+）：返回**不可变**列表，不能再改
> - `stream.collect(Collectors.toList())`：返回**可变**列表（ArrayList）
>
> 名字几乎一样，能力不同。想要"不可变"的话，前者更直接；想让下游继续改，得用后者。
> 顺带：想用 collect 拿到不可变结果，写 `Collectors.toUnmodifiableList()`。

> [!question]- Q3：为什么一条流不能用两次？
> 因为 Stream 不是"数据容器"，是**一次性的管道**。它内部持有源数据的游标，走完就到头了。
> 想再走一遍，得从源重新 `stream()` 一条新的。
> 这也是为什么"保留 Stream 变量以后再用"必踩坑——变量存在，流已经死了。

## 📎 补充：两个值得记住的

> [!note] 1. `toMap` 的 key 重复，第三个参数能救
> 默认 `Collectors.toMap(k, v)` 遇到重复 key 直接抛异常。
> 加第三个参数指定"冲突时留谁"就没事了：
> ```java
> // 冲突时保留旧值
> .collect(Collectors.toMap(Dog::getName, Dog::getAge, (oldV, newV) -> oldV));
> ```
> 这个设计其实很对——**它逼你想清楚"重复了该怎么办"**，而不是偷偷替你选一个。

> [!note] 2. jshell 里写多行流式，用括号包住
> 直接换行会被当成多条语句报错。但**未闭合的括号会让 jshell 等续行**：
> ```
> jshell> (List.of(1,2,3).stream()
>    ...>  .filter(x -> x > 1)
>    ...>  .toList())
> ```
> 看到 `...>` 提示就是在等续行，最后把括号补上就能执行。
> 这个技巧不只对 Stream 有用，任何长表达式都能这么拆。
