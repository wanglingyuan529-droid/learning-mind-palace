# 2026-11-10 学习日记

> 今天学方法引用。开篇有个疑问没想通：既然只是把 `->` 换成 `::`，那它凭什么说"更直观"？

## 🎯 今天一句话

**方法引用不是在"缩短写法"，是在说"这段逻辑我不用写，现成的那个方法就是它"——省下的不是字符，是一次重复定义。**

## ✅ 学到了什么

### Java · 方法引用到底是什么

**定义**：当 lambda 体**只是调用一个已经存在的方法**，别的什么都不干时，可以不用写 lambda，直接写那个方法的名字。

```java
// lambda 版：我写了个匿名函数，但它只干了一件事——调 trim
s -> s.trim()

// 方法引用版：既然只是调 trim，那我直接指过去
String::trim
```

**所以它成立的前提很硬**：lambda 体里**除了调用这个方法，不能再有别的动作**。

```java
s -> s.trim()               // ✅ 能转成 String::trim
s -> s.trim().length()      // ❌ 有后续操作，转不了
s -> s.length() > 5         // ❌ 有比较运算，转不了
```

### Java · 五种形式（重点是参数怎么对上）

这是方法引用唯一的难点：**你不写参数了，但参数没消失，是被自动分配了**。

| # | 写法 | 等价于 | 参数怎么分配 |
| --- | --- | --- | --- |
| ① | `类名::静态方法` | `(a, b) -> 类名.静态方法(a, b)` | 参数**原样**传进去 |
| ② | `对象名::实例方法` | `(a, b) -> 对象.实例方法(a, b)` | 参数**原样**传进去 |
| ③ | `this::方法` / `super::方法` | `(a) -> this.方法(a)` | 参数原样传，调用者是 this/super |
| ④ | `类名::new` | `(a, b) -> new 类名(a, b)` | 参数**传给构造方法** |
| ⑤ | `类名::实例方法` | `(obj, a) -> obj.实例方法(a)` | **第一个参数当调用者**，其余当方法参数 |

**① ② ④ 都好理解，参数照搬就行。真正的坑是 ② 和 ⑤ 的区别**：

```java
// ② 对象名::方法名 —— 对象是现成的
System.out::println        // 等价 (x) -> System.out.println(x)

// ⑤ 类名::方法名 —— 对象还没定，用参数当对象
String::equals             // 等价 (a, b) -> a.equals(b)
String::length             // 等价 (s) -> s.length()
```

**一句话分清**：
- ② 里**调用者是固定的**（某个已经存在的对象）
- ⑤ 里**调用者是第一个参数**（谁传进来谁当）

### Java · 关于「更直观」这个疑问

你觉得"没感觉更直观，只是短了"，这个感觉**是对的，而且很关键**。

方法引用的"直观"不是普遍成立的，它只在一种情况下真的赢：

```java
// ✅ 这时候方法引用确实更清楚——方法名本身就是完整语义
list.forEach(System.out::println);
names.sort(String::compareToIgnoreCase);

// 🤔 这时候就未必了——还要回头查这个方法干了什么
list.stream().map(String::trim).collect(...)     // 还行，trim 意思明确
list.stream().map(SomeUtil::f7).collect(...)     // 不行，f7 是什么鬼
```

**判断标准**：方法名能不能自己把话说清楚。

- 能（`println`、`trim`、`length`）→ 方法引用更好，少一层噪音
- 不能（`f7`、`process`、`handle` 这种含糊名字）→ 老老实实写 lambda，至少还能看出参数

所以别把方法引用当"必须用的新语法"。**它是可选写法，不是升级**。IDEA 会提示你能不能换，换不换看你判断哪个更好读。

## 🔍 自测（先遮住答案）

> [!question]- Q1：`String::length` 和 `System.out::println`，哪个是「类名::实例方法」？
> `String::length`。
> 它等价于 `(s) -> s.length()`——对象是参数传进来的，所以用**类名**引用。
> 而 `System.out::println` 的 `System.out` 是一个**已经存在的对象**，属于「对象名::实例方法」，等价于 `(x) -> System.out.println(x)`。
> 区别就一句：**对象已经存在就用对象名，对象要靠参数传进来就用类名。**

> [!question]- Q2：`list.sort((a, b) -> a.compareTo(b))` 能改成方法引用吗？
> 能，写成 `list.sort(String::compareTo)`（假设是 String 列表）。
> 因为 lambda 体只有"调用 `a.compareTo(b)`"这一件事，符合方法引用的前提。
> `a` 是第一个参数，正好当调用者，所以是「类名::实例方法」形式。

> [!question]- Q3：为什么 `s -> s.trim().length()` 不能转成方法引用？
> 因为它干了**两件事**：先 trim，再取 length。
> 方法引用只能指向**一个**方法，没法表达"先 A 后 B"。
> 记住判据：**lambda 体里除了一个方法调用，不能有任何其他操作**（不能有比较、不能有链式后续、不能有多步）。

## 📎 补充：两个值得记住的

> [!note] 1. 方法引用不是新东西，是 lambda 的"特例语法"
> 编译后，方法引用和 lambda 走的是同一套底层机制（`invokedynamic`）。
> 它不是性能优化，也不是必须掌握的新能力——**写不写只看可读性**。
> IDEA 会给你 "Can be replaced with method reference" 的提示，那只是建议，不是警告。

> [!note] 2. `modifiable` 和昨天的 `Immutable` 是一对
> 昨天学的不可变集合，本质就是"把 modifiable 变成 not modifiable"。
> 这两个词在 Java 文档里经常成对出现，看到 `unmodifiable` 就是在说"别改了"。
