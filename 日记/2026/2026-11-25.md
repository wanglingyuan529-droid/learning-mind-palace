# 2026-11-25 学习日记

> 今天一口气过了 IO 的高级部分：缓冲流、转换流、序列化、打印流、压缩流。
> 你自己也说了「很多都没记住，都是英文单词」——这很正常，今天这些**类名本来就是一堆英文词的组合**。下面把它们拆开讲。

## 🎯 今天一句话

**今天学的这五种流，全是「装饰器」：它们不产生数据，只是在别的流外面包一层，加一项能力——缓冲、编码、格式化、压缩。**

## ✅ 学到了什么

### Java · 缓冲流：省的是系统调用

| 字节 | 字符 |
| --- | --- |
| `BufferedInputStream` / `BufferedOutputStream` | `BufferedReader` / `BufferedWriter` |

**为什么快**：你说的"不用经常访问硬盘"方向对，但更准确的说法是——

> **省的是「系统调用」的次数。**

每次真正读写文件，程序都要从"用户态"切到"内核态"（这是有固定开销的）。普通流是**读一个字节就切一次**；缓冲流是**先在内存里攒够一批，切一次把它们全送出去**。

所以它快不是因为"硬盘慢"（这个大家都知道），是因为**"每次交换都要交过路费"**，缓冲流把过路费摊薄了。

**两个用法要点**：

```java
// ① 缓冲流必须套在一个普通流外面（它自己不会连文件）
BufferedReader br = new BufferedReader(new FileReader("a.txt"));

// ② 缓冲流 + 自己的数组，是最快的手动组合
byte[] buf = new byte[8192];
```

注意：缓冲流再套一层数组，**不是你多此一举**——缓冲流内部有自己的小缓冲，你外面的数组是"批量取货"，两层目的不同。

### Java · 转换流：字节 → 字符的桥

| 字节转字符 | 字符转字节 |
| --- | --- |
| `InputStreamReader` | `OutputStreamWriter` |

**它的唯一作用**：在**字节流和字符流之间架一座桥**，并且**在这座桥上指定编码**。

```java
new InputStreamReader(new FileInputStream("a.txt"), StandardCharsets.UTF_8);
```

这就是 11-23 说的那句"字符流底层是字节流 + 编码转换"的**具体实现**——`FileReader` 内部其实就包了一个 `InputStreamReader`。

### Java · 序列化：对象 ↔ 字节

| 方向 | 名字 | 干什么 |
| --- | --- | --- |
| 对象 → 字节 | **序列化** `serialize` | 把对象状态写成一串字节 |
| 字节 → 对象 | **反序列化** `deserialize` | 从字节把对象"复活" |

你说"就像加密解密"——方向对，但有个**关键差别**：序列化**不是加密**，它只是编码，**任何人拿到那串字节都能还原出对象**。别拿它当安全措施。

**用途**（你写的两个都对）：
- 网络传输（RPC、Socket 传对象）
- 缓存（把对象存到文件/Redis）

**门槛**：类必须实现 `Serializable` 接口。

### Java · 你问的 transient：标记「这个字段别存」

这是今天你明确说"不是很懂"的地方，讲清楚：

**`transient` = 「这个字段不参与序列化」。**

反序列化后，这个字段会变成**默认值**（对象是 `null`，数字是 `0`）。

**为什么要这么做**——常见四种场景：

| 场景 | 例子 |
| --- | --- |
| **敏感信息** | 密码、token——写成字节存到文件里等于泄露 |
| **不可序列化的东西** | 文件句柄、`Thread`、`InputStream`——它们本身就没法写成字节 |
| **能重算出来的数据** | 缓存、派生字段——存了也白存，反序列化后重算就行 |
| **和当前环境绑定的数据** | 连接、线程池——换个进程就没用了 |

**一句话**：`transient` 是给"**不该跟着对象走**"的字段贴的标签。

### Java · 静态字段为什么也不参与序列化

这个和 `transient` 不同，是**根本性的**：

> 序列化保存的是**对象的状态**，而静态字段属于**类**，不属于任何对象。

再换个角度想：如果静态字段被序列化了，反序列化时**要往哪覆盖？**——同一个 JVM 里类只加载一次，可能已经有别的对象在用这个静态字段了，你还原回来就会把它覆盖掉。这是个没法解决的问题，所以干脆不存。

### Java · 打印流 & 压缩流

| 流 | 干什么 |
| --- | --- |
| `PrintStream`（字节）/ `PrintWriter`（字符） | 直接 `print` / `println` 各种类型，**不用手动转换** |
| `System.out` | 就是一个 `PrintStream`——你天天在用 |
| `GZIPInputStream` / `GZIPOutputStream` | gzip 压缩/解压 |
| `ZipInputStream` / `ZipOutputStream` | zip 格式，能处理多个条目 |

## 🔍 自测（先遮住答案）

> [!question]- Q1：为什么缓冲流快？说得更准确一点。
> 不是因为"硬盘慢"（这是常识），而是因为**减少了系统调用的次数**。
> 每次真正碰文件，都要从用户态切到内核态，这个切换的成本是固定的。
> 普通流读 1 字节切一次；缓冲流先在内存攒一批，切一次把整批送出去——**过路费被摊薄了**。

> [!question]- Q2：给一个 `transient` 的字段反序列化后，它是什么值？
> **默认值。** 对象是 `null`，基本类型是 `0`/`false`。
> 因为它的值**从来没被写进那串字节里**，还原时自然没有东西可以填。
> 所以读出来用它之前，通常得自己补一次（重新计算，或者从别的来源赋值）。

> [!question]- Q3：为什么静态字段不参与序列化，和 transient 是同一个原因吗？
> **不是同一个原因。**
> - `transient`：人为标记，"我不想存这个字段"
> - 静态字段：**根本不属于对象**，它属于类。序列化的定义就是"保存对象状态"，静态字段不在这个范围内
>
> 还有个现实理由：如果存了，反序列化时覆盖谁的？同一个 JVM 里类只有一个，可能已经有别的对象在用它了。

## 📎 补充：两个值得记住的

> [!note] 1. 今天这五种流，全是「装饰器模式」
> 这是它们共同的骨架：**每个流都不自己产生数据，只是在另一个流外面包一层，多给一项能力**。
>
> ```
> FileInputStream              ← 最底层：真的连文件
>  └ BufferedInputStream       ← 包一层：加缓冲
>    └ ...                     ← 还能继续包：加压缩、加编码
> ```
>
> 所以你看到 `new A(new B(new C(file)))` 这种嵌套不是"故意写复杂"，是**装饰器的必然形态**——每层只管一件事。
> 这个模式在设计模式里叫 **Decorator**，IO 流是它最经典的例子。

> [!note] 2. 「学底层有什么用，实际开发不这么写」——这个判断是对的
> 你说"实际开发不会这样嵌套写"，**完全正确**。真实项目里会用工具类（Hutool、Commons IO、Guava），一行读完一个文件。
>
> 但底层不是白学的，它买的是**两样东西**：
>
> | 买到什么 | 什么时候用到 |
> | --- | --- |
> | **看懂异常** | 报 `Stream Closed` / `Too many open files` 时，你知道是哪一层没关 |
> | **会做判断** | 工具类封装的是什么？它的默认缓冲多大？它会不会自动关流？——懂底层才敢信它 |
>
> 打个比方：**开车不需要会造发动机，但听到异响能判断是哪儿的问题，这就是底层知识的价值。**
> 你今天的嵌套写法是"拆开看零件"，明天用工具类是"直接开整车"——两者不冲突。
