# 2026-11-16 学习日记

> 今天三块：Java 的 File 类（配六个递归练习）、Docker 命令地图、英语 10 词。

## 🎯 今天一句话

**`File` 只是「一个路径」，不是「一个文件」——它存不存在都得另说。这一句拎清楚了，File 类的坑就少了一半。**

## ✅ 学到了什么

### Java · File 的本质

你写的这句是今天最有价值的一句：

> File 是一个路径，不是一个真正存在的文件，他也可以不存在。

**完全正确。** `new File("xxx.txt")` 只是把一串字符包起来，**它不检查、不创建、不报错**。真正的检查在 `exists()` 那一步。

代价是：**路径写错了不会当场报错**，要等到你调 `exists()` / `listFiles()` / 读文件时才发现。所以 File 类的 bug 往往"错得很晚"。

### Java · 六个练习，其实都是同一个套路

| 练习 | 单个流程 | 递归点 |
| --- | --- | --- |
| 查找单个文件 | 判断当前这个是不是目标 | 是目录就再进去找 |
| 递归查找文件 | 同上 | 遍历子文件，每个再调自己 |
| 递归删除文件夹 | 删一个文件 | 先把子项全删干净，再删自己 |
| 递归算目录大小 | 累加一个文件的大小 | 子目录再进去累加 |
| 创建文件 | `createNewFile()` | 父目录不存在得先 `mkdirs()` |
| 统计文件数量 | 计数 +1 | 子目录再进去数 |

你说的"递归就是循环一遍实现单个流程，再自己调用自己"——这句话抓住了递归的全部要点：**先想清楚"处理一个"怎么写，然后问一句"如果是目录呢"，答案就是"进去再来一遍"**。

### Java · 几个该知道的坑

方法确实不难，但这几处会绊人：

| 坑 | 说明 |
| --- | --- |
| **`delete()` 删不掉非空目录** | 返回 `false`，不报错。必须递归删干净子项 |
| **`mkdir()` vs `mkdirs()`** | 前者父目录不存在就失败，后者会连父目录一起建 |
| **相对路径的基准是「当前工作目录」** | 不是项目目录，也不是类所在目录。IDE 里跑和命令行里跑可能不一样 |
| **路径分隔符** | Windows `\`，Linux/macOS `/`。跨平台写法是 `/`（Java 会自动转）或 `File.separator` |
| **File 不管文件内容** | 它只管路径和元数据（名字、大小、时间）。读写内容要用 IO 流 |

### Docker · 命令地图

你列了 20 条命令，按用途归一下类，比一条条背好记：

| 用途 | 命令 | 说明 |
| --- | --- | --- |
| **看镜像** | `docker images` / `-a` | `-a` 连中间层镜像一起显示 |
| | `docker search` | 去仓库搜 |
| | `docker inspect` | 查详情（ID、配置、网络） |
| **看容器** | `docker ps` / `-a` / `-q` | 默认只看运行中的；`-a` 包含已停止；`-q` 只出 ID |
| | `docker stats` | 实时资源占用（CPU/内存/网络） |
| **跑容器** | `docker run` | 下面的选项都是它的 |
| | `-it` | `-i` 交互 + `-t` 终端，一起用才能进去敲命令 |
| | `-d` | 后台运行（detached） |
| | `-p 8080:80` | 端口映射，**宿主:容器** |
| | `--name` | 给容器起名，不然只有随机名字 |
| | `--rm` | 容器退出后自动删掉，适合一次性任务 |
| **进容器** | `docker exec -it 名字 bash` | 在**运行中**的容器里开个新终端 |
| **日志** | `docker logs` | 看容器的标准输出 |
| **停止/删除** | `docker stop` / `docker rm` | 停止 / 删除容器 |
| | `docker rmi` | 删除镜像 |
| **传文件** | `docker cp` | 宿主和容器之间拷文件 |
| **搬运镜像** | `docker save` / `docker load` | 存成 tar / 从 tar 恢复 |

**两条最容易被记混**：

- `docker rm` 删**容器**，`docker rmi` 删**镜像**（i = image）
- `docker exec` 进**运行中**的容器；容器停了得先 `docker start`

## 🔍 自测（先遮住答案）

> [!question]- Q1：`new File("不存在的文件.txt")`，会抛出异常吗？
> **不会。** 这一行只是把一个路径字符串包装成对象，什么都不检查。
> 你要等到调 `exists()`、`listFiles()`、`delete()` 或者读文件时，才会知道它到底存不存在。
> 这正是"File 是路径不是文件"的实际含义——**它的 bug 往往错得很晚**。

> [!question]- Q2：为什么 `delete()` 删不掉一个有子文件的目录？
> 因为操作系统本身就不允许删除非空目录（`rmdir` 也只删空目录）。
> Java 遵守同样的规则，`File.delete()` 遇到非空目录直接返回 `false`，**不抛异常**，所以特别容易被忽略。
> 正确做法就是今天练的那个：**递归**——先把子项一条条删干净，最后再删这个目录本身。

> [!question]- Q3：`docker exec -it` 和 `docker run -it` 都是"进容器敲命令"，区别在哪？
> - `docker run -it`：**新建**一个容器，并直接进去。容器是因为这条命令才诞生的。
> - `docker exec -it 名字 bash`：在**已经运行中**的容器里**另开**一个终端。容器本来就在那儿。
>
> 记住顺序：run 是"生一个再进"，exec 是"进已有的"。容器已经停了，exec 是进不去的。

## 📎 补充：两个值得记住的

> [!note] 1. 递归写不出来时，先写"处理一个"的版本
> 今天六个练习全是同一个套路。写的时候不要一上来就想"怎么递归"，先老老实实把**单个文件**的处理写完（是不是目标、多大、加不加 1）。
> 然后在末尾问一句：**"如果它是目录呢？"** —— 答案就是"进去 traversal 每个子项，再调自己一遍"。
> 递归的出口就在里面：不是目录了，就走单个流程。

> [!note] 2. 路径分隔符，Java 其实帮你兜了一半
> Windows 用 `\`，Linux/macOS 用 `/`。但 Java 里字符串写 `/` 也能在 Windows 上正常工作，`new File("a/b/c.txt")` 是跨平台的。
> 真正需要小心的是**从配置文件里读进来的路径**（别人可能写成 `\`），以及**反斜杠转义**：`"C:\new\test.txt"` 里的 `\n` `\t` 会被当成转义字符，得写成 `"C:\\new\\test.txt"` 或 `"C:/new/test.txt"`。
