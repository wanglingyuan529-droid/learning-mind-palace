# 2026-11-26 学习日记

> 今天没学新知识，只做了一件事：写了一份 Java / Python 全栈路线图，给群友参考用的。

## 🎯 今天一句话

**路线图的价值不在于「列全了」，而在于它让人看清自己现在站在第几项——你正好在第 1 项的尾巴上。**

## ✅ 今天做了什么

### 写了一份 [[Java全栈路线图]]

26 项，一条直线走到底：JavaSE → 数据库 → 框架 → 中间件 → 前端 → 容器编排 → AI 生态 → Python 侧 → 综合项目。

三个结构上的特点：

**① 分了三段**

| 段 | 内容 |
| --- | --- |
| 第 1–14 项 | **传统后端栈**（Java 生态 + 前端 + 运维） |
| 第 15–19 项 | **AI 生态**（大模型 → Spring AI → MCP → RAG → 多智能体） |
| 第 20–26 项 | **Python 侧 + 收尾** |

**② 留了岔路**

结尾那两条备注很实用：

> Python 学到「能跑通、能改开源项目」就够，不做第二语言深造。
> 只在 Java 生态里做 AI 的话，第 20–24 项只走 20、21 两项即可。

这不是"必须全走完"的清单，是**带分支的路径**——这在路线图里是个加分项，很多人写路线图只会一条线排到底。

**③ 对照你自己的进度**

按这份路线图，你现在的位置：

| 项 | 状态 |
| --- | --- |
| **第 1 项 JavaSE** | 🔄 **正在进行**（集合、IO 流、异常都在这项里面） |
| 第 2 项 MySQL | ⬜ 还没开始 |

所以这不是一份"我要从头学"的计划，是"我走完第一段之前，后面还有多少"的地图。

## 📎 一个结构上的观察

这份路线图把**动手项目全部放在最后一项**（第 26 项"综合项目"）。

好处是：前面每一项都能专注学，不用被项目分心。
代价是：第 1–25 项走完，中间学到的东西**没有地方沉淀**——比如第 5 项 Redis，学完不练，到第 15 项时可能已经忘得差不多了。

这不是说路线图写错了（给别人指路时，一条干净的线比一堆分叉好用）。只是**自己走的时候**，中间那些项目怎么揉进去，得另想办法。
