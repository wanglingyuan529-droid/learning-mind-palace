## 📎 把忘掉的名字补回来

```
Collection（单列集合，一次装一个元素）
├── List        有序、可重复         → ArrayList / LinkedList
└── Set         不可重复（无序）      → HashSet / TreeSet / LinkedHashSet

Map（双列集合，一次装一个键值对）
├── HashMap          无序，查询最快
├── LinkedHashMap    保插入顺序
└── TreeMap          按键排序
```

**对照你的记忆**：

| 你的说法 | 正式名字 | 怎么记 |
| --- | --- | --- |
| 单列集合，一次一个数据 | **`Collection`** | Collection 是"收集"，一个一个收 |
| 双列集合，key-value | **`Map`** | Map 是"地图"，一个名字对应一个地点 |

**关键点**：`List` 和 `Set` **不是**和 `Map` 平级的两个东西，它们是 `Collection` 的**子接口**。你之前的理解里，"单列"是两个具体的东西，实际上它是一个**父接口 + 两个子接口**。这层父子关系补上，名字就跟着回来了。

## 📝 关于「Java 类名太长」这件事

> java 太猎奇了，这个类的名字长的快从屏幕里面戳到我了

这个吐槽有道理，而且不是你的问题。补两句背景：

**为什么这么长**：Java 早期定的规矩是"名字要自己解释自己"，不靠注释。所以：

| 类名 | 拆开看 |
| --- | --- |
| `InputStreamReader` | Input(输入) + Stream(流) + Reader(读取器) |
| `BufferedOutputStream` | Buffered(带缓冲的) + Output + Stream |
| `UnsupportedOperationException` | Unsupported(不支持) + Operation(操作) + Exception(异常) |

**它们都是"定语 + 主体"的堆叠**，知道每个词的意思就能拆开，不用整体背。所以背单词对读 Java 类名是有直接回报的——你现在这个单词量，读这些名字应该越来越顺。

**另一个原因**：Java 是**多层组合**的体系（一个流套一个流），名字必须把"套了哪几层"写出来，否则分不清 `FileReader` 和 `BufferedReader` 差在哪。

## 🔍 今天的复盘

> [!question]- 自问一：如果让你现在把 List / Set / Map 三个词和它们的特点对上，能做到吗？
> - **List**：有序、可重复，按下标访问 → `ArrayList`、`LinkedList`
> - **Set**：不可重复，靠 `hashCode + equals` 去重 → `HashSet`；要保序用 `LinkedHashSet`；要排序用 `TreeSet`
> - **Map**：键值对，键唯一 → `HashMap`、`LinkedHashMap`、`TreeMap`
> 记不住细节没关系，先把"List 是排队的，Set 是不重样的，Map 是一对一的"这三句握住。

> [!note] "忘"的三种类型，处理方式完全不同
> 1. **结构忘了**（不知道为什么这么做）→ 要回头重学，最费时
> 2. **名字忘了**（知道是什么，叫不出来）→ **查一次就回来**，最便宜
> 3. **手生**（知道也写不出来）→ 练一次就回来
>
> 你今天属于第 2 种，是好消息。第 2 种最怕的是"啊我记得是那个什么来着"就过去了——**当场查一下、写下来，就永久解决**。
