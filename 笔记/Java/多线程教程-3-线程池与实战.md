## 0. 综合练习（23–28）

> 这几个练习都围绕 **多个线程操作同一份数据**，用来巩固线程安全。

### 练习 1：抢红包（24）

**需求**：100 元分 5 个红包，5 个人同时抢，不能重复、不能超发。

#### 第一步：随机分红包（保证总额不变）

```java
import java.util.*;

public class RedPacket {
    public static void main(String[] args) {
        double total = 100;
        int count = 5;                  // 分成 5 个
        List<Double> packets = new ArrayList<>();

        double remain = total;
        int remainCount = count;
        Random r = new Random();

        for (int i = 1; i <= count; i++) {
            double money;
            if (i == count) {
                money = remain;                     // 最后一个拿剩下的
            } else {
                // 二倍均值法：最多拿剩余金额平均值的 2 倍
                double max = remain / remainCount * 2;
                money = Math.round((1 + r.nextDouble() * (max - 1)) * 100) / 100.0;

                // 保证后面的人至少能拿到 0.01
                if (money > remain - (remainCount - 1) * 0.01) {
                    money = remain - (remainCount - 1) * 0.01;
                }
            }
            money = Math.round(money * 100) / 100.0;
            packets.add(money);
            remain -= money;
            remainCount--;
        }

        System.out.println("红包分配: " + packets);
        double sum = packets.stream().mapToDouble(Double::doubleValue).sum();
        System.out.println("总和: " + String.format("%.2f", sum));
    }
}
```

**实测输出：**

```
红包分配: [37.73, 9.66, 13.14, 26.88, 12.59]
总和: 100.00
```

**算法要点：二倍均值法**

```
每次最多拿：剩余金额 / 剩余人数 * 2
```

**这样既保证每个人拿到的不会太夸张（不会一个人拿 99 块），又保证总额能分完。**

#### 第二步：多线程抢红包

```java
public class RedPacketGrab {
    public static void main(String[] args) throws Exception {
        List<Double> pool = new ArrayList<>(List.of(37.73, 9.66, 13.14, 26.88, 12.59));
        List<String> winners = Collections.synchronizedList(new ArrayList<>());

        Thread[] threads = new Thread[5];
        for (int i = 0; i < 5; i++) {
            final int id = i + 1;
            threads[i] = new Thread(() -> {
                synchronized (pool) {                 // 关键：同步保护
                    if (pool.isEmpty()) {
                        System.out.println("  线程" + id + " 没抢到");
                        return;
                    }
                    double m = pool.remove(0);
                    winners.add("线程" + id + " 抢到 " + m);
                }
            });
            threads[i].start();
        }

        for (Thread t : threads) t.join();
        winners.forEach(System.out::println);
        System.out.println("剩余红包: " + pool.size());
    }
}
```

**实测：**

```
线程1 抢到 37.73
线程2 抢到 9.66
线程3 抢到 13.14
线程4 抢到 26.88
线程5 抢到 12.59
剩余红包: 0
```

**关键点**：
- `synchronized (pool)` 保证"检查 + 取出"是原子的
- 不加锁的话，可能出现"两个线程都判断 pool 非空，然后都去 remove(0)"，导致越界或抢到同一个

### 练习 2：抽奖（25）

**需求**：从一个奖池里抽奖，每个奖品只能被抽一次。

```java
import java.util.*;
import java.util.concurrent.atomic.AtomicInteger;

public class Lottery {
    static List<String> prizes = new ArrayList<>(List.of("一等奖", "二等奖", "三等奖", "谢谢参与"));
    static final Object LOCK = new Object();

    public static void main(String[] args) throws Exception {
        Thread[] threads = new Thread[5];
        for (int i = 0; i < 5; i++) {
            final int id = i + 1;
            threads[i] = new Thread(() -> {
                synchronized (LOCK) {
                    if (prizes.isEmpty()) {
                        System.out.println("  线程" + id + "：奖品抽完了");
                        return;
                    }
                    int idx = new Random().nextInt(prizes.size());
                    String p = prizes.remove(idx);     // 抽到的移除，不会重复
                    System.out.println("  线程" + id + " 抽到: " + p);
                }
            });
            threads[i].start();
        }
        for (Thread t : threads) t.join();
        System.out.println("剩余奖品: " + prizes);
    }
}
```

**核心**：**抽到的从池子里移除**（`remove(idx)`），天然防重复。

### 练习 3：多线程统计并求和（26–27）

**需求**：1~1000 分成 10 段，10 个线程各算一段，最后求和。

#### 解法一：共享变量 + 同步

```java
public class SumTask {
    static int total = 0;
    static final Object LOCK = new Object();

    public static void main(String[] args) throws Exception {
        Thread[] threads = new Thread[10];
        int per = 1000 / 10;    // 每段 100 个数

        for (int i = 0; i < 10; i++) {
            final int start = i * per + 1;
            final int end = (i + 1) * per;
            threads[i] = new Thread(() -> {
                int sum = 0;
                for (int n = start; n <= end; n++) sum += n;

                synchronized (LOCK) {      // 汇总时要加锁
                    total += sum;
                }
            });
            threads[i].start();
        }

        for (Thread t : threads) t.join();
        System.out.println("总和: " + total);    // 应为 500500
    }
}
```

**实测：500500** ✅

#### 解法二：用 AtomicInteger（原子类，更轻量）

```java
import java.util.concurrent.atomic.AtomicInteger;

public class SumTask2 {
    static AtomicInteger total = new AtomicInteger(0);

    public static void main(String[] args) throws Exception {
        Thread[] threads = new Thread[10];
        int per = 100;

        for (int i = 0; i < 10; i++) {
            final int start = i * per + 1;
            final int end = (i + 1) * per;
            threads[i] = new Thread(() -> {
                int sum = 0;
                for (int n = start; n <= end; n++) sum += n;
                total.addAndGet(sum);        // 原子累加，不用 synchronized
            });
            threads[i].start();
        }

        for (Thread t : threads) t.join();
        System.out.println("总和: " + total.get());   // 500500
    }
}
```

**`AtomicInteger` 比 `synchronized` 轻量**（底层用 CAS 无锁算法）。

### 练习 4：多线程之间的比拼（28）

**简单的多线程性能测试**：单线程 vs 多线程的耗时对比。

```java
public class SpeedTest {
    public static void main(String[] args) throws Exception {
        long start, end;

        // 单线程
        start = System.currentTimeMillis();
        long sum1 = 0;
        for (long i = 0; i < 100_000_000L; i++) sum1 += i;
        end = System.currentTimeMillis();
        System.out.println("单线程: " + (end - start) + "ms，结果 " + sum1);
    }
}
```

**注意**：**不是所有任务多线程都更快**——任务本身太多线程反而更慢（线程切换开销）。

## 1. 线程池（29）

### 1.1 为什么需要线程池

**每来一个任务就 `new Thread()` 的代价：**

| 问题 | 原因 |
|---|---|
| 创建线程慢 | 系统调用、分配栈内存 |
| 线程太多 | 内存爆炸、CPU 频繁切换 |
| 无法管理 | 不知道有多少线程、无法统一关闭 |

**线程池的答案**：

> **提前创建好一批线程，任务来了直接给线程执行，执行完线程回到池子里等下一个任务。**

**好处**：
- **复用线程**（不用反复创建销毁）
- **控制并发数**（不会无限开线程）
- **管理方便**（统一关闭、监控）

### 1.2 四种常见线程池（Executors 工厂）

```java
import java.util.concurrent.*;

// ① 固定大小
ExecutorService pool1 = Executors.newFixedThreadPool(3);

// ② 缓存型（线程数弹性，按需创建）
ExecutorService pool2 = Executors.newCachedThreadPool();

// ③ 单线程池（只有一个线程）
ExecutorService pool3 = Executors.newSingleThreadExecutor();

// ④ 定时/周期任务
ScheduledExecutorService pool4 = Executors.newScheduledThreadPool(2);
```

| 类型 | 特点 | 适用 |
|---|---|---|
| `newFixedThreadPool(n)` | 固定 n 个线程 | **最常用**，数量稳定 |
| `newCachedThreadPool()` | 按需创建，空闲 60 秒回收 | 短小任务、突发流量 |
| `newSingleThreadExecutor()` | 只有 1 个线程 | 需要顺序执行 |
| `newScheduledThreadPool(n)` | 支持定时/周期任务 | 定时任务 |

### 1.3 基本用法

```java
public class ThreadPoolDemo {
    public static void main(String[] args) throws Exception {
        ExecutorService pool = Executors.newFixedThreadPool(3);

        for (int i = 1; i <= 5; i++) {
            final int n = i;
            pool.submit(() -> {
                System.out.println("  任务" + n + " 由 " + Thread.currentThread().getName() + " 执行");
            });
        }

        pool.shutdown();                                       // 关闭池（不再接新任务）
        pool.awaitTermination(5, TimeUnit.SECONDS);            // 等待现有任务执行完
        System.out.println("线程池任务完成");
    }
}
```

**实测输出：**

```
  任务2 由 pool-1-thread-2 执行
  任务3 由 pool-1-thread-3 执行
  任务1 由 pool-1-thread-1 执行
  任务4 由 pool-1-thread-3 执行
  任务5 由 pool-1-thread-1 执行
线程池任务完成
```

**注意**：**5 个任务，只用了 3 个线程**（线程复用）。任务4、5 复用了线程1、3。

### 1.4 提交任务的两种方式

```java
// execute：无返回值
pool.execute(() -> System.out.println("跑"));

// submit：有返回值（Future）
Future<Integer> future = pool.submit(() -> 1 + 2 + 3);
System.out.println(future.get());    // 6
```

### 1.5 带返回值的 Callable（实测）

```java
ExecutorService pool = Executors.newFixedThreadPool(2);
Future<Integer> f1 = pool.submit(() -> 1 + 2 + 3);
Future<Integer> f2 = pool.submit(() -> 4 + 5 + 6);

System.out.println("f1 结果: " + f1.get());    // 6
System.out.println("f2 结果: " + f2.get());    // 15
pool.shutdown();
```

**实测：6 和 15。** `get()` 会阻塞，直到任务算完。

### 1.6 关闭线程池

```java
pool.shutdown();        // 温和关闭：不接新任务，等现有任务执行完
pool.shutdownNow();     // 强制关闭：中断正在执行的任务
pool.awaitTermination(5, TimeUnit.SECONDS);   // 等待关闭完成
```

**⚠️ `shutdown()` 之后不能再提交任务**（会抛 `RejectedExecutionException`）。

## 2. 自定义线程池（30）

### 2.1 七大参数

**`ThreadPoolExecutor` 的构造器有 7 个参数，这是理解线程池的核心：**

```java
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    2,                          // 1. corePoolSize：核心线程数
    4,                          // 2. maximumPoolSize：最大线程数
    60,                         // 3. keepAliveTime：非核心线程空闲存活时间
    TimeUnit.SECONDS,           // 4. unit：时间单位
    new ArrayBlockingQueue<>(10),  // 5. workQueue：任务队列
    Executors.defaultThreadFactory(),  // 6. threadFactory：线程工厂
    new ThreadPoolExecutor.AbortPolicy()  // 7. handler：拒绝策略
);
```

### 2.2 参数详解

| 参数 | 含义 | 怎么理解 |
|---|---|---|
| `corePoolSize` | 核心线程数 | **常驻**的线程，不会销毁 |
| `maximumPoolSize` | 最大线程数 | 队列满了才创建到这么多 |
| `keepAliveTime` | 空闲存活时间 | 非核心线程闲着多久被销毁 |
| `unit` | 时间单位 | 秒/毫秒 |
| `workQueue` | 任务队列 | 核心线程忙时，任务先排队 |
| `threadFactory` | 线程工厂 | 创建线程的方式（可自定义名字） |
| `handler` | 拒绝策略 | 队列满 + 线程满时怎么办 |

### 2.3 执行流程（必须理解）

```
任务来了：
  ① 核心线程有空闲 → 直接执行
  ② 核心线程都忙 → 放进队列排队
  ③ 队列满了 → 创建非核心线程（最多到 maximumPoolSize）
  ④ 队列满 + 线程数已达最大 → 执行拒绝策略
```

**画成图：**

```
                    ┌─────────────┐
  任务提交 ────────►│ 核心线程池   │ 忙？
                    └──────┬──────┘
                           │ 都忙
                           ▼
                    ┌─────────────┐
                    │   任务队列   │ 满了？
                    └──────┬──────┘
                           │ 满了
                           ▼
                    ┌─────────────┐
                    │ 非核心线程   │ 已达最大？
                    └──────┬──────┘
                           │ 满了
                           ▼
                       拒绝策略
```

### 2.4 四种拒绝策略

| 策略 | 行为 | 适用 |
|---|---|---|
| `AbortPolicy`（默认） | **抛异常** `RejectedExecutionException` | 默认，能发现问题 |
| `CallerRunsPolicy` | **调用者线程自己执行** | 不丢任务，降级 |
| `DiscardPolicy` | **丢弃，不报错** | 可丢弃的任务 |
| `DiscardOldestPolicy` | **丢掉队列最老的，再提交** | 要新的不要旧的 |

### 2.5 实测

```java
public class CustomPool {
    public static void main(String[] args) throws Exception {
        ThreadPoolExecutor executor = new ThreadPoolExecutor(
            2, 4, 60, TimeUnit.SECONDS,
            new ArrayBlockingQueue<>(10),
            new ThreadPoolExecutor.AbortPolicy()
        );

        for (int i = 1; i <= 6; i++) {
            final int n = i;
            executor.execute(() -> {
                try { Thread.sleep(100); } catch (InterruptedException e) {}
                System.out.println("  任务" + n + " 线程=" + Thread.currentThread().getName());
            });
        }

        executor.shutdown();
        executor.awaitTermination(10, TimeUnit.SECONDS);
        System.out.println("完成");
    }
}
```

**实测输出：**

```
  任务1 线程=pool-3-thread-1
  任务2 线程=pool-3-thread-2
  任务4 线程=pool-3-thread-2
  任务3 线程=pool-3-thread-1
  任务5 线程=pool-3-thread-2
  任务6 线程=pool-3-thread-1
```

**观察**：6 个任务用了 2 个线程（因为核心线程=2，其他任务排队）。

## 4. 线程池多大合适（32）

**这是面试高频题，但答案不是固定的。**

### 4.1 经验公式

| 任务类型 | 线程数 | 理由 |
|---|---|---|
| **CPU 密集型**（计算为主） | **N + 1** | N = 核数，多 1 个是为了在某个线程偶发阻塞时补位 |
| **IO 密集型**（等待为主） | **2N**（或 N * (1 + 等待时间/计算时间)） | 等 IO 时线程闲着，多开能提高吞吐 |

### 4.2 怎么判断类型

| 类型 | 特征 | 例子 |
|---|---|---|
| CPU 密集型 | 大量计算、很少等待 | 加密、压缩、复杂算法 |
| IO 密集型 | 大量等待网络/磁盘 | 数据库查询、HTTP 请求、文件读写 |

### 4.3 实际原则

> **公式只是起点，真正合适的大小要靠压测。**

**建议流程**：
1. 先按公式估算（CPU 密集 N+1，IO 密集 2N）
2. 压测观察：CPU 利用率、响应时间、吞吐量
3. 调整：CPU 打满而响应慢 → 减少线程；CPU 用不满而线程排队 → 增加

**不要照搬公式**，不同业务差异很大。

## 5. 额外扩展内容（33）

### 5.1 JUC 是什么

**JUC = `java.util.concurrent`**，Java 并发工具包的缩写。

课程标题里的"JUC"指的就是这个包，里面有：
- 线程池（`ExecutorService`）
- 并发集合（`ConcurrentHashMap`、`BlockingQueue`）
- 原子类（`AtomicInteger`）
- 锁（`ReentrantLock`）
- 同步工具（`CountDownLatch`、`Semaphore`）

### 5.2 常用的 JUC 工具（了解）

**AtomicInteger：原子加减**

```java
AtomicInteger count = new AtomicInteger(0);
count.incrementAndGet();    // +1 并返回（线程安全）
count.addAndGet(5);         // +5
```

**ConcurrentHashMap：线程安全的 Map**

```java
ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();
map.put("a", 1);     // 线程安全，不用自己加锁
```

**CountDownLatch：等待多个任务完成**

```java
CountDownLatch latch = new CountDownLatch(3);   // 等 3 个
// 每个任务完成后 latch.countDown()
latch.await();       // 等全部完成
```

**Semaphore：控制并发数**

```java
Semaphore sem = new Semaphore(3);   // 最多 3 个并发
sem.acquire();      // 拿许可
sem.release();      // 还许可
```

**这些在面试和实际工作中都会遇到，但本课程只到线程池，后面可以单独学。**

## 7. 常见错误速查

| ❌ 错法 | ✅ 对法 | 后果 |
|---|---|---|
| `newFixedThreadPool` 用无界队列 | 用 `ThreadPoolExecutor` 指定有界队列 | OOM（队列无限涨） |
| 队列用 `LinkedBlockingQueue()` 不带容量 | 指定容量 | 同上 |
| 拒绝策略用 `DiscardPolicy` | 用 `AbortPolicy` 或 `CallerRunsPolicy` | 任务悄悄丢失 |
| `shutdown()` 后继续 submit | 检查状态 | `RejectedExecutionException` |
| 忘记 `awaitTermination` | 加等待 | 主线程提前退出 |
| 线程池大小照搬公式 | 压测后调整 | 性能不达预期 |
| 每个任务都 `new Thread` | 用线程池 | 线程爆炸 |

## 记忆口诀

> **线程池复用线程，核心线程常驻，队列满了才扩；**
> **七参数：核心、最大、存活、单位、队列、工厂、拒绝；**
> **执行顺序：核心 → 队列 → 非核心 → 拒绝；**
> **拒绝策略四种，默认 Abort 抛异常；**
> **CPU 密集 N+1，IO 密集 2N，公式只是起点要压测；**
> **抢红包二倍均值，多线程统计用 AtomicInteger。**
