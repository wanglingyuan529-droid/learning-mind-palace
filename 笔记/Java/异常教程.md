# Java 异常教程（小白版）

> 用途：学习笔记 · 定位：讲得细、面向刚入门
> 覆盖：异常-01 ~ 11
> 所有示例和输出都是在本机 JDK 27 上用 jshell 实测跑出来的

---

## 0. 异常是什么

**程序运行中"出问题了"——比如除零、空指针、数组越界——Java 用"异常对象"来表示这件事。**

```java
int x = 10 / 0;   // 抛 ArithmeticException
```

**异常不是"崩溃"，而是一个可以被"接住"的对象。** 接住了程序就能继续跑，接不住就终止。

## 1. 异常体系（01）

### 1.1 一张图记住

```
            Throwable（所有异常的祖宗）
           /         \
        Error       Exception（这才是我们要处理的）
        （错误）      /            \
                    /              \
          RuntimeException       编译时异常
          （运行时异常）          （如 IOException）
          ├─ NullPointerException
          ├─ ArithmeticException
          ├─ ArrayIndexOutOfBoundsException
          └─ ...
```

**实测继承关系：**

```
Throwable 的父类是 Object
Error 的父类是 Throwable
Exception 的父类是 Throwable
RuntimeException 的父类是 Exception
IOException 的父类是 Exception
ArithmeticException 的父类是 RuntimeException
NullPointerException 的父类是 RuntimeException
```

### 1.2 三兄弟的区别

| 类型 | 是什么 | 要不要处理 |
|---|---|---|
| **Error** | 严重错误（栈溢出、内存不够），程序基本救不回来 | 通常**不处理** |
| **RuntimeException** | 运行时异常，代码写错了才会出现 | **可以不处理**（但应该避免） |
| **编译时异常** | 编译期就强制你处理（如 IO） | **必须处理**，否则编译不过 |

**一句话**：**Error 是"天灾"，RuntimeException 是"人祸"，编译时异常是"必须签字的合同"。**

## 2. 编译时异常 vs 运行时异常（02）

### 2.1 运行时异常：不处理也能编译

```java
public static void main(String[] args) {
    int x = 10 / 0;   // 编译通过，运行时抛 ArithmeticException
}
```

**实测：**

```java
try {
    System.out.println(10 / 0);
} catch (ArithmeticException e) {
    System.out.println(e.getMessage());    // "/ by zero"
}
```

**常见运行时异常：**

| 异常 | 什么时候出现 |
|---|---|
| `NullPointerException` | 调用了 null 的方法/属性 |
| `ArithmeticException` | 除零 |
| `ArrayIndexOutOfBoundsException` | 数组越界 |
| `ClassCastException` | 类型转换错误 |
| `NumberFormatException` | 字符串转数字失败 |

### 2.2 编译时异常：不处理直接编译报错

```java
// ❌ 编译错误：未处理的异常 IOException
throw new IOException("文件不存在");
```

**必须 try-catch 或 throws 声明：**

```java
// 方式 1：try-catch
try {
    throw new IOException("文件不存在");
} catch (IOException e) {
    System.out.println("捕获: " + e.getMessage());
}

// 方式 2：throws（把锅甩给调用者）
void readFile() throws IOException {
    throw new IOException("文件不存在");
}
```

**常见编译时异常：** `IOException`、`FileNotFoundException`、`SQLException`、`ParseException`、`ClassNotFoundException`。

### 2.3 怎么判断是哪种

**看继承关系，不看名字：**

| 继承自 | 类型 | 是否强制处理 |
|---|---|---|
| `RuntimeException` | 运行时异常 | 否 |
| `Exception`（但不继承 RuntimeException） | 编译时异常 | **是** |

**别被名字骗了**：`IllegalArgumentException`、`IndexOutOfBoundsException` 名字里没有 `Runtime`，但都继承 `RuntimeException`，属于**运行时异常**。

**自己写异常时**：

```java
class MyException extends RuntimeException  // 运行时（不强制处理）
class MyException extends Exception        // 编译时（强制处理）
```

## 3. 异常的两个作用（03）

### 作用 1：提示错误

```java
int[] arr = new int[2];
arr[5] = 1;    // ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 2
```

**异常信息直接告诉你：哪里错了、错在哪、为什么。**

### 作用 2：控制流程（跳转）

**异常能让程序"跳出"当前逻辑，直接跳到 catch：**

```java
try {
    System.out.println("第一行");
    int x = 10 / 0;
    System.out.println("第二行");   // ❌ 不会执行，直接跳到 catch
} catch (ArithmeticException e) {
    System.out.println("catch 捕获到了");
}
System.out.println("之后继续执行");
```

**输出：**

```
第一行
catch 捕获到了
之后继续执行
```

**这就是"异常跳转"**——出问题的地方后面的代码不执行，直接去 catch。

## 4. JVM 默认处理方式（04）

**如果你不写 try-catch，异常会一直往上抛，最后到 JVM：**

```
① 把异常信息打印到控制台（红字堆栈）
② 终止程序
```

**实测：**

```java
System.out.println(10 / 0);
System.out.println("这行不会执行");
```

**输出：**

```
Exception java.lang.ArithmeticException: / by zero
      at (#4:1)
```

**第二行确实没执行**——程序被终止了。

**所以：不处理的异常 = 程序崩溃。** 这就是为什么需要 try-catch。

## 5. try-catch 捕获异常（05）

### 5.1 基本语法

```java
try {
    // 可能出问题的代码
} catch (异常类型 变量名) {
    // 出问题后怎么处理
}
```

**例子：**

```java
try {
    int x = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("除法出错了: " + e.getMessage());
}
System.out.println("程序继续执行");
```

### 5.2 finally：不管出不出问题都执行

```java
try {
    System.out.println("try");
    int x = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("catch");
} finally {
    System.out.println("finally 一定会执行");
}
```

**输出：**

```
try
catch
finally 一定会执行
```

**finally 的用途**：关闭资源（文件、数据库连接、网络）。

**实测：finally 在 return 之前执行**

```java
int test() {
    try {
        return 1;
    } finally {
        System.out.println("finally 在 return 之前执行");
    }
}
test();
// 输出：finally 在 return 之前执行
// 返回：1
```

### 5.3 多个 catch：子类在前，父类在后

```java
try {
    String s = null;
    s.length();
} catch (NullPointerException e) {
    System.out.println("空指针");
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("数组越界");
} catch (Exception e) {
    System.out.println("兜底");
}
```

**顺序很重要**：`Exception` 是父类，**必须放最后**。放前面的话，后面的子类 catch 永远轮不到，编译器直接报错：

```
编译错误：已被捕获
```

### 5.4 try-with-resources（自动关闭资源）

```java
try (MyResource r = new MyResource("文件")) {
    System.out.println("使用 " + r.name);
}
// 自动调用 r.close()
```

**实测输出：**

```
打开 文件
使用 文件
关闭 文件
```

**只要类实现了 `AutoCloseable`，try 结束后自动关闭**，不用写 finally。

## 6. 捕获异常"灵魂四问"（06–07）

> **这四问是面试/考试高频，也是理解异常执行流程的关键。**

### 问 ①：如果 try 中没有遇到问题，怎么执行？

**答：执行完 try，跳过 catch，继续往下。**

```java
try {
    System.out.println("try 里执行");
} catch (Exception e) {
    System.out.println("catch 不会执行");
}
System.out.println("之后继续");
```

**输出：**

```
try 里执行
之后继续
```

### 问 ②：如果 try 中遇到了问题，try 下面的代码还会执行吗？

**答：不会。直接跳到 catch，然后继续往下。**

```java
try {
    System.out.println("第一行");
    int x = 10 / 0;
    System.out.println("第二行（不会执行）");
} catch (ArithmeticException e) {
    System.out.println("catch 捕获到了");
}
System.out.println("之后继续");
```

**输出：**

```
第一行
catch 捕获到了
之后继续
```

### 问 ③：如果出现的问题没有被捕获，程序如何运行？

**答：JVM 默认处理——打印堆栈 + 终止程序。**

```java
System.out.println(10 / 0);    // 没 catch
System.out.println("不会执行");
```

**输出：**

```
Exception in thread "main" java.lang.ArithmeticException: / by zero
```

**程序终止，后面的代码全不执行。**

### 问 ④：同时有可能出现多个异常，怎么处理？

**答：写多个 catch，按顺序匹配（子类在前，父类在后）。**

```java
try {
    String s = null;
    s.length();
} catch (NullPointerException e) {
    System.out.println("捕获 NPE");
} catch (Exception e) {
    System.out.println("兜底");
}
```

**注意**：**只会进入第一个匹配的 catch**，后面的不再执行。

## 7. 异常中的常见方法（08）

```java
try {
    int[] arr = new int[2];
    arr[5] = 1;
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println(e.getMessage());           // 错误信息
    System.out.println(e.toString());             // 异常类型 + 信息
    System.out.println(e.getClass().getName());   // 异常类名
    e.printStackTrace();                          // 打印完整堆栈（调试用）
}
```

**实测输出：**

| 方法 | 输出 |
|---|---|
| `getMessage()` | `Index 5 out of bounds for length 2` |
| `toString()` | `java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 2` |
| `getClass().getName()` | `java.lang.ArrayIndexOutOfBoundsException` |
| `printStackTrace()` | 完整堆栈（类名 + 行号 + 调用链） |

**怎么选：**
- **调试时**：`printStackTrace()`（能看到哪一行出错）
- **给用户提示**：`getMessage()`（简短）
- **日志记录**：`toString()` 或 `getMessage()`

## 8. 抛出异常：throw vs throws（09）

### 8.1 throw：在方法里"扔"一个异常

```java
void checkAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("年龄不能为负: " + age);
    }
    System.out.println("年龄合法: " + age);
}

try {
    checkAge(-1);
} catch (IllegalArgumentException e) {
    System.out.println("捕获: " + e.getMessage());    // 捕获: 年龄不能为负: -1
}
checkAge(18);   // 年龄合法: 18
```

**`throw` 用在方法体内，后面跟异常对象。**

### 8.2 throws：在方法签名上"声明"可能抛的异常

```java
void readFile() throws IOException {
    throw new IOException("模拟读取失败");
}

try {
    readFile();
} catch (IOException e) {
    System.out.println("readFile 抛了: " + e.getMessage());
}
```

**`throws` 用在方法声明上，告诉调用者"我可能会抛这个异常，你看着办"。**

### 8.3 对比

| | throw | throws |
|---|---|---|
| 位置 | **方法体内** | **方法签名上** |
| 后面跟 | **异常对象**（`new XxxException()`） | **异常类名**（`IOException`） |
| 作用 | 真正抛出异常 | 声明可能抛出 |
| 例子 | `throw new RuntimeException("x")` | `void f() throws IOException` |

**记忆**：`throw` 是"扔"（动作），`throws` 是"声明"（承诺）。

## 9. 综合练习（10）

### 练习：模拟用户登录

```java
class LoginException extends RuntimeException {
    LoginException(String msg) { super(msg); }
}

void login(String username, String password) {
    if (!"admin".equals(username)) {
        throw new LoginException("用户名不存在: " + username);
    }
    if (!"123456".equals(password)) {
        throw new LoginException("密码错误");
    }
    System.out.println("登录成功");
}

try {
    login("admin", "wrong");
} catch (LoginException e) {
    System.out.println("登录失败: " + e.getMessage());
}
```

**输出：**

```
登录失败: 密码错误
```

## 10. 自定义异常（11）

### 10.1 两种自定义异常

**运行时异常（不强制处理）：**

```java
class AgeException extends RuntimeException {
    public AgeException(String message) {
        super(message);
    }
}
```

**编译时异常（强制处理）：**

```java
class FileException extends Exception {
    public FileException(String message) {
        super(message);
    }
}
```

### 10.2 使用

```java
// 运行时异常：直接 throw，调用者可 catch 可不 catch
throw new AgeException("年龄异常");

// 编译时异常：必须 try-catch 或 throws
throw new FileException("文件异常");
```

### 10.3 自定义异常的作用

**让错误信息更"业务化"**：

```java
// 不自定义
throw new RuntimeException("余额不足");

// 自定义
throw new BalanceNotEnoughException("余额不足，当前余额: 100，需要: 200");
```

**好处**：
1. 错误类型一目了然（看到 `BalanceNotEnoughException` 就知道是余额问题）
2. 可以携带额外信息
3. 调用方可以"精确捕获"

### 10.4 自定义异常的规范写法

```java
public class BalanceNotEnoughException extends RuntimeException {
    private final double balance;
    private final double required;

    public BalanceNotEnoughException(double balance, double required) {
        super("余额不足：当前 " + balance + "，需要 " + required);
        this.balance = balance;
        this.required = required;
    }

    public double getBalance() { return balance; }
    public double getRequired() { return required; }
}
```

**要点**：
- 继承 `RuntimeException`（简化调用方）或 `Exception`（强制处理）
- 提供带 message 的构造器
- 需要时携带额外字段

### 10.5 异常链（进阶）

**把底层异常包成业务异常，保留根因：**

```java
try {
    int x = 10 / 0;
} catch (ArithmeticException e) {
    throw new MyException("业务处理失败", e);   // 传入 cause
}
```

**实测：**

```
外层异常: 业务处理失败
根因: java.lang.ArithmeticException: / by zero
```

**这是"不丢失原始错误信息"的标准做法。**

## 11. 一页速查表

### 结构

| 写法 | 用途 |
|---|---|
| `try { } catch (E e) { }` | 捕获处理 |
| `try { } catch (E e) { } finally { }` | 捕获 + 收尾 |
| `try (资源) { }` | 自动关闭资源 |
| `throw new XxxException("msg")` | 抛出异常 |
| `void f() throws E` | 声明可能抛出 |

### 异常体系

| 类型 | 继承自 | 是否强制处理 |
|---|---|---|
| `Error` | `Throwable` | 否（不该处理） |
| `RuntimeException` | `Exception` | 否 |
| 编译时异常 | `Exception` | **是** |

### 常见方法

| 方法 | 输出 |
|---|---|
| `getMessage()` | 错误信息 |
| `toString()` | 类型 + 信息 |
| `printStackTrace()` | 完整堆栈 |

### 常见运行时异常

| 异常 | 原因 |
|---|---|
| `NullPointerException` | 调 null 的方法 |
| `ArithmeticException` | 除零 |
| `ArrayIndexOutOfBoundsException` | 数组越界 |
| `ClassCastException` | 类型转换错误 |
| `NumberFormatException` | 字符串转数字失败 |

## 12. 常见错误速查

| ❌ 错法 | ✅ 对法 | 后果 |
|---|---|---|
| `catch (Exception e)` 放最前面 | 子类在前，父类在后 | 编译错误 |
| 不处理编译时异常 | try-catch 或 throws | 编译不过 |
| `catch` 里什么都不写 | 至少打印日志 | 出问题查不到 |
| 用 `catch (Exception e)` 捕获一切 | 精确捕获能处理的类型 | 掩盖真实问题 |
| `throw` 写类名 | `throw new XxxException()` | 编译错误 |
| `throws` 后面写对象 | `throws 异常类名` | 编译错误 |
| 自定义异常继承 `Throwable` | 继承 `Exception` 或 `RuntimeException` | 不规范 |
| 吞掉异常（catch 后不处理） | 打印日志或重新抛出 | 问题被隐藏 |
