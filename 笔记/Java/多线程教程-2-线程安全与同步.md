## 0. 线程安全问题（12）

### 0.1 先看一个"出错"的例子

**需求**：三个窗口卖 100 张票，不能超卖。

```java
public class TicketDemo {
    static int ticket = 100;      // 共享票数

    public static void main(String[] args) throws Exception {
        Runnable sell = () -> {
            while (true) {
                if (ticket <= 0) break;

                try { Thread.sleep(10); } catch (InterruptedException e) {}

                ticket--;
                System.out.println(Thread.currentThread().getName() + " 卖出一张，剩 " + ticket);
            }
        };

        Thread a = new Thread(sell, "窗口A");
        Thread b = new Thread(sell, "窗口B");
        Thread c = new Thread(sell, "窗口C");
        a.start(); b.start(); c.start();
        a.join(); b.join(); c.join();

        System.out.println("最终票数: " + ticket);
    }
}
```

**实测结果（关键部分）：**

```
窗口A 卖出一张，剩 0
窗口C 卖出一张，剩 -2
窗口B 卖出一张，剩 -1
最终票数: -2
```

**⚠️ 票数变成了 -2！超卖了 2 张。**

### 0.2 为什么会出现这个问题

**问题出在 `ticket--` 这一行。它不是"一步完成"的，而是三步：**

```
① 读：把 ticket 的值读进内存（ticket = 1）
② 减：算出 0
③ 写：把 0 写回 ticket
```

**如果两个线程同时执行：**

```
线程A：读 ticket=1 ──► 减 ──► 写 ticket=0
线程B：      读 ticket=1 ──► 减 ──► 写 ticket=0     ← 也读到了 1，写 0
结果：两个线程各卖一张，票只少了 1，但实际卖出去 2 张
```

**这叫"竞态条件"（Race Condition）**——多个线程同时读写同一份数据，结果取决于执行顺序。

### 0.3 线程安全的三个条件

**满足这三个条件才会出问题：**

1. **多线程**（至少两个线程）
2. **共享数据**（访问同一个变量）
3. **有写操作**（不只是读）

**只有一个线程？没事。只读不写？没事。**

## 1. 同步代码块（13）

### 1.1 解决思路

**让"读-减-写"这三步**在一起**，中间不能被别的线程插进来。**

```java
synchronized (锁对象) {
    // 需要"原子性"执行的代码
}
```

### 1.2 代码

```java
public class TicketDemoSync {
    static int ticket = 100;
    static final Object LOCK = new Object();    // 锁对象

    public static void main(String[] args) throws Exception {
        Runnable sell = () -> {
            while (true) {
                synchronized (LOCK) {
                    if (ticket <= 0) break;
                    try { Thread.sleep(10); } catch (InterruptedException e) {}
                    ticket--;
                    System.out.println(Thread.currentThread().getName() + " 卖出，剩 " + ticket);
                }
            }
        };

        Thread a = new Thread(sell, "A");
        Thread b = new Thread(sell, "B");
        Thread c = new Thread(sell, "C");
        a.start(); b.start(); c.start();
        a.join(); b.join(); c.join();

        System.out.println("最终票数: " + ticket);
    }
}
```

**实测：最终票数 0** ✅（不再超卖）

### 1.3 同步的原理

```
线程A 进入 synchronized:
    ① 尝试获取锁
    ② 拿到了 → 执行代码
    ③ 执行完 → 释放锁

线程B 进入 synchronized:
    ① 尝试获取锁
    ② 锁被 A 占着 → 阻塞等待（BLOCKED 状态）
    ③ A 释放后 → B 拿到锁，执行
```

**关键**：**同一时刻只有一个线程能进 synchronized 块。**

### 1.4 锁对象怎么选

**锁对象可以是任意对象，但有个铁律：**

> **多个线程必须用同一个锁对象，才能真正互斥。**

```java
static final Object LOCK = new Object();    // ✅ 静态共享

// 如果是每个线程都 new 一个，那就等于没锁
Object lock = new Object();   // ❌ 每个线程都不一样
```

**标准做法**：
- 静态方法 → 用 `类名.class` 或静态 final 对象
- 实例方法 → 用 `this`
- 第三方对象 → 静态 final 对象

## 2. 同步代码块的两个细节（14）

### 细节 1：锁的范围要"刚刚好"

**范围太大**：所有线程都串行，多线程没意义。

```java
// ❌ 整个循环都锁住，等于单线程
synchronized (LOCK) {
    while (true) { ... }
}

// ✅ 只锁关键操作
while (true) {
    synchronized (LOCK) {
        ticket--;
    }
}
```

**范围太小**：锁不住真正有问题的代码。

```java
// ❌ 只锁了打印，没锁 ticket--
System.out.println("卖出");
synchronized (LOCK) { ticket--; }

// ✅ 读-判断-减-打印，都在锁内
synchronized (LOCK) {
    if (ticket <= 0) break;
    ticket--;
}
```

### 细节 2：synchronized 里别做耗时操作

**锁里写 `sleep`、网络请求、读大文件——会让所有线程干等。**

```java
// ❌ 锁里 sleep，其他线程全卡住
synchronized (LOCK) {
    Thread.sleep(1000);    // 这一秒里别人都进不来
}

// ✅ 该睡的地方放锁外面
Thread.sleep(1000);
synchronized (LOCK) { ... }
```

## 3. 同步方法（15）

### 3.1 把 synchronized 写在方法上

**同步代码块**：

```java
public void sell() {
    synchronized (this) {
        // ...
    }
}
```

**同步方法**（等价写法）：

```java
public synchronized void sell() {
    // ...
}
```

### 3.2 同步方法的锁对象

| 方法类型 | 锁对象 |
|---|---|
| **实例方法**（非 static） | **`this`**（当前对象） |
| **静态方法**（static） | **`类名.class`** |

```java
class Ticket {
    static int ticket = 100;

    // 静态同步方法：锁是 Ticket.class
    public static synchronized void sell() {
        ticket--;
    }

    // 实例同步方法：锁是 this
    public synchronized void sell2() {
        ticket--;
    }
}
```

**⚠️ 关键坑**：**静态同步方法和实例同步方法用不同的锁，不能互斥！**

### 3.3 同步代码块 vs 同步方法

| | 同步代码块 | 同步方法 |
|---|---|---|
| 粒度 | 可以只锁一部分代码 | 锁整个方法 |
| 灵活度 | 高 | 低 |
| 性能 | 更好（锁的范围小） | 差一点 |
| 用途 | 精确控制 | 简单场景 |

**推荐**：能用同步代码块就用代码块（粒度更细）。

## 4. Lock 锁（16）

### 4.1 为什么还要 Lock

`synchronized` 是"自动"的：进去自动加锁、出来自动释放。

**但有时候需要更灵活的控制：**
- 尝试获取锁（拿不到就走，不干等）
- 可以中断的锁
- 读写锁

**`Lock` 接口提供更灵活的能力。**

### 4.2 ReentrantLock 基本用法

```java
import java.util.concurrent.locks.*;

public class LockDemo {
    static int ticket = 100;
    static Lock lock = new ReentrantLock();

    public static void main(String[] args) throws Exception {
        Runnable sell = () -> {
            while (true) {
                lock.lock();              // 加锁
                try {
                    if (ticket <= 0) break;
                    try { Thread.sleep(10); } catch (InterruptedException e) {}
                    ticket--;
                    System.out.println(Thread.currentThread().getName() + " 卖出，剩 " + ticket);
                } finally {
                    lock.unlock();        // 解锁（必须放 finally）
                }
            }
        };

        Thread a = new Thread(sell, "A");
        Thread b = new Thread(sell, "B");
        a.start(); b.start(); a.join(); b.join();
        System.out.println("最终票数: " + ticket);
    }
}
```

**实测：最终票数 0** ✅

### 4.3 ⚠️ 最重要的坑：unlock 必须放 finally

```java
// ❌ 如果 break 或抛异常，unlock 没执行 → 死锁
lock.lock();
if (ticket <= 0) break;    // 直接跳出了，锁没释放！
ticket--;
lock.unlock();

// ✅ 放 finally 里
lock.lock();
try {
    if (ticket <= 0) break;
    ticket--;
} finally {
    lock.unlock();
}
```

**`synchronized` 会自动释放，`Lock` 不会——忘了 unlock 就是灾难。**

### 4.4 synchronized vs Lock

| | synchronized | Lock |
|---|---|---|
| 释放 | **自动** | **手动（必须 finally）** |
| 灵活性 | 低 | 高 |
| 尝试锁 | 无 | `tryLock()` |
| 可中断 | 无 | `lockInterruptibly()` |
| 性能 | JDK 6+ 优化后接近 | 高并发场景略优 |
| 推荐 | 简单场景 | 复杂场景 |

**实际建议**：**能用 synchronized 就用它**（简单、不会忘记释放）。需要高级功能才用 Lock。

## 5. 死锁（17）

### 5.1 死锁是什么

**两个线程各自拿着一把锁，同时等对方手里的锁——谁也动不了。**

### 5.2 复现

```java
public class DeadLock {
    public static void main(String[] args) throws Exception {
        Object lockA = new Object();
        Object lockB = new Object();

        Thread t1 = new Thread(() -> {
            synchronized (lockA) {
                System.out.println("t1 拿到锁A");
                try { Thread.sleep(100); } catch (InterruptedException e) {}
                synchronized (lockB) {
                    System.out.println("t1 拿到锁B");
                }
            }
        });

        Thread t2 = new Thread(() -> {
            synchronized (lockB) {
                System.out.println("t2 拿到锁B");
                try { Thread.sleep(100); } catch (InterruptedException e) {}
                synchronized (lockA) {
                    System.out.println("t2 拿到锁A");
                }
            }
        });

        t1.start();
        t2.start();
        t1.join(3000);    // 最多等 3 秒
        t2.join(3000);

        System.out.println("t1 alive: " + t1.isAlive() + "，t2 alive: " + t2.isAlive());
    }
}
```

**实测输出：**

```
t1 拿到锁A
t2 拿到锁B
（卡住不动）
t1 alive: true，t2 alive: true
```

**两个线程都卡在 `synchronized`，永远等下去。**

### 5.3 一个真实的发现

**死锁不仅让线程卡住，还会让 JVM 无法退出**（因为非守护线程还在跑）。

我实测时，程序卡住不结束，**只能用 kill 强杀**。

**这就是死锁在真实项目里的危害**：服务卡死、内存泄漏、只能重启。

### 5.4 死锁的四个必要条件

| 条件 | 意思 |
|---|---|
| 互斥 | 锁只能被一个线程占 |
| 占有且等待 | 拿着一个锁，还在等另一个 |
| 不可剥夺 | 锁不能被抢走 |
| **循环等待** | A 等 B 的锁，B 等 A 的锁 |

**破坏任意一个就能避免死锁**。实际最常见的是破坏"循环等待"：**约定固定的加锁顺序**。

```java
// 所有线程都先拿 A 再拿 B（不要反过来）
```

## 6. 等待唤醒机制（18–20）

### 6.1 场景：生产者-消费者

**厨师做包子（生产者），食客吃包子（消费者）**：

- 桌上满了 → **厨师不能继续做**，要等
- 桌上空了 → **食客不能吃**，要等
- 做好一个 → **通知食客**
- 吃掉一个 → **通知厨师**

### 6.2 wait / notify 机制

**`Object` 类提供的三个方法（必须在 synchronized 里调用）：**

| 方法 | 作用 |
|---|---|
| `wait()` | 释放锁，进入等待，直到被唤醒 |
| `notify()` | 唤醒一个等待的线程 |
| `notifyAll()` | 唤醒所有等待的线程 |

### 6.3 完整代码

```java
public class ProducerConsumer {
    static final Object LOCK = new Object();
    static int count = 0;           // 桌上包子数
    static final int MAX = 5;       // 最多 5 个

    public static void main(String[] args) throws Exception {
        Thread cook = new Thread(() -> {
            while (true) {
                synchronized (LOCK) {
                    if (count >= MAX) {
                        try { LOCK.wait(); } catch (InterruptedException e) { return; }
                    }
                    if (count >= MAX) continue;

                    count++;
                    System.out.println("  厨师做好一个，桌上 " + count);
                    LOCK.notifyAll();
                }
            }
        });

        Thread eater = new Thread(() -> {
            while (true) {
                synchronized (LOCK) {
                    if (count == 0) {
                        try { LOCK.wait(); } catch (InterruptedException e) { return; }
                    }
                    if (count == 0) continue;

                    count--;
                    System.out.println("  食客吃掉一个，桌上 " + count);
                    LOCK.notifyAll();
                }
            }
        });

        cook.setDaemon(true);
        eater.setDaemon(true);
        cook.start();
        eater.start();
        Thread.sleep(1200);
        System.out.println("演示结束");
        cook.interrupt();
        eater.interrupt();
    }
}
```

**实测输出（节选）：**

```
  厨师做好一个，桌上 1
  厨师做好一个，桌上 2
  厨师做好一个，桌上 3
  厨师做好一个，桌上 4
  厨师做好一个，桌上 5
  食客吃掉一个，桌上 4
  食客吃掉一个，桌上 3
  ...
  厨师做好一个，桌上 1
```

**桌满时厨师停，桌空时食客停。**

### 6.4 wait 和 sleep 的区别（高频面试题）

| | `wait()` | `sleep()` |
|---|---|---|
| 属于谁 | **Object 类** | **Thread 类** |
| 释放锁吗 | **✅ 释放** | ❌ 不释放 |
| 需要 synchronized 吗 | **✅ 必须** | ❌ 不需要 |
| 怎么醒 | `notify()` / `notifyAll()` / 超时 | 时间到 |
| 状态 | WAITING / TIMED_WAITING | TIMED_WAITING |

**记忆**：**wait 会放锁，sleep 死死抓着锁不放。**

### 6.5 为什么用 while 而不是 if（14 集细节）

```java
// ❌ if 有风险
if (count == 0) {
    LOCK.wait();
}
count--;    // 醒来时，count 可能又被别人改了

// ✅ while 更安全
while (count == 0) {
    LOCK.wait();     // 醒来后再检查一次
}
count--;
```

**原因**：线程被唤醒后，**条件可能又变了**（被其他线程抢先）。

**这叫"虚假唤醒"问题**，标准写法是 `while` 循环检查条件。

## 7. 阻塞队列（21）

### 7.1 更简单的生产者-消费者

**Java 提供了 `BlockingQueue`，内部已经帮你实现了"满了等、空了等"的逻辑。**

```java
import java.util.concurrent.*;

BlockingQueue<String> queue = new ArrayBlockingQueue<>(2);   // 容量 2

// 生产者
queue.put("产品1");     // 队列满时，这里会阻塞（自动等待）

// 消费者
String item = queue.take();   // 队列空时，这里会阻塞（自动等待）
```

### 7.2 实测代码

```java
public class BlockingQueueDemo {
    public static void main(String[] args) throws Exception {
        BlockingQueue<String> queue = new ArrayBlockingQueue<>(2);

        Thread producer = new Thread(() -> {
            try {
                for (int i = 1; i <= 5; i++) {
                    queue.put("产品" + i);
                    System.out.println("  生产: 产品" + i);
                }
            } catch (InterruptedException e) {}
        });

        Thread consumer = new Thread(() -> {
            try {
                for (int i = 1; i <= 5; i++) {
                    Thread.sleep(300);
                    System.out.println("  消费: " + queue.take());
                }
            } catch (InterruptedException e) {}
        });

        producer.start();
        consumer.start();
        producer.join();
        consumer.join();
        System.out.println("生产消费完成");
    }
}
```

**实测输出：**

```
  生产: 产品1
  生产: 产品2
  生产: 产品3        ← 队列满（容量2），产品3 等在门外
  消费: 产品1
  消费: 产品2
  生产: 产品4
  消费: 产品3
  生产: 产品5
  消费: 产品4
  消费: 产品5
```

**注意：生产 3 时先阻塞，等消费 1 之后才继续。**

### 7.3 阻塞队列的方法

| 方法 | 队列满/空时 | 特点 |
|---|---|---|
| `put(e)` | **满时阻塞** | 等 |
| `take()` | **空时阻塞** | 等 |
| `add(e)` | 满时抛异常 | 不推荐 |
| `offer(e)` | 满时返回 false | 不阻塞 |
| `poll()` | 空时返回 null | 不阻塞 |

**推荐 `put`/`take`**（自动处理阻塞）。

### 7.4 为什么要用阻塞队列

**自己写 wait/notify 很麻烦**（要 while、要 notifyAll、要防虚假唤醒）。

**阻塞队列一行搞定，而且线程安全。**

## 8. 一页速查表

### 线程安全

| 方案 | 写法 | 注意 |
|---|---|---|
| 同步代码块 | `synchronized (锁) { }` | 锁对象要共享 |
| 同步方法 | `public synchronized void f()` | 锁是 this |
| 静态同步方法 | `public static synchronized void f()` | 锁是 类.class |
| Lock | `lock.lock()` + `try` + `finally { lock.unlock(); }` | **必须 unlock** |

### 等待唤醒

| 方法 | 作用 | 前提 |
|---|---|---|
| `wait()` | 释放锁等待 | 在 synchronized 里 |
| `notify()` | 唤醒一个 | 在 synchronized 里 |
| `notifyAll()` | 唤醒全部 | 在 synchronized 里 |
| `put()` / `take()` | 阻塞队列自动等待 | 无 |

### 死锁

**四个条件**：互斥、占有且等待、不可剥夺、循环等待。

**预防**：固定加锁顺序。

## 9. 常见错误速查

| ❌ 错法 | ✅ 对法 | 后果 |
|---|---|---|
| 锁对象每个线程 new 一个 | 静态共享锁对象 | 锁不住 |
| 锁范围太大 | 只锁关键代码 | 变单线程 |
| 锁范围太小 | 把判断+操作一起锁 | 还是超卖 |
| `Lock` 忘记 `unlock` | 放 `finally` | 死锁 |
| `wait` 用 `if` 判断 | 用 `while` | 虚假唤醒出错 |
| `wait` 在没 synchronized 的地方调 | 放进 synchronized | 抛 IllegalMonitorStateException |
| 静态和实例同步方法混用 | 注意锁对象不同 | 不互斥 |
| 加锁顺序不固定 | 约定统一顺序 | 死锁 |

## 记忆口诀

> **多线程 + 共享数据 + 写操作 = 线程安全问题；**
> **synchronized 锁对象必须共享，锁范围刚刚好；**
> **静态同步锁是类，实例同步锁是 this；**
> **Lock 必须 finally 里 unlock；**
> **wait 放锁、sleep 不放锁；**
> **wait 用 while 不用 if；**
> **死锁四条件，循环等待最常见；**
> **阻塞队列省事，put/take 自动等。**
