# 多线程教程（一）：基础与线程生命周期

> 用途：学习笔记 · 定位：讲得细、面向刚入门 · **代码完整可运行**
> 覆盖：多线程&JUC-01 ~ 11
> 所有示例都在本机 JDK 27 上实测跑过

---

## 0. 什么是多线程（01）

### 0.1 一句话

**多线程 = 让程序同时干几件事。**

**单线程**：一条路走到底，做完一件事再做下一件。
**多线程**：同时开几条路，几件事并行推进。

**生活类比**：
- 单线程：食堂只有一个窗口，排一队
- 多线程：食堂开三个窗口，三个队同时动

### 0.2 进程 vs 线程

| | 进程 | 线程 |
|---|---|---|
| 是什么 | 一个运行中的程序 | 进程里的执行单元 |
| 资源 | 有自己的内存空间 | **共享进程的内存** |
| 开销 | 大 | 小 |
| 例子 | 一个 QQ 客户端 | QQ 里的消息接收、文件传输 |

**关键**：**一个进程可以有多个线程，它们共享同一块内存。**

**共享内存是好事（通信方便），也是坏事（会互相干扰）——这就是"线程安全"问题的根源。**

## 1. 并发与并行（02）

**这两个词经常被混用，但不一样：**

| | 并发（Concurrency） | 并行（Parallelism） |
|---|---|---|
| 意思 | **多个任务交替执行** | **多个任务同时执行** |
| 硬件要求 | 单核就能"并发" | 需要多核 |
| 类比 | 一个人轮流做三件事 | 三个人同时做三件事 |

**实测（看看你的机器几个核）：**

```java
System.out.println("CPU 核数: " + Runtime.getRuntime().availableProcessors());
```

**本机实测**：返回一个大于 1 的数（多核），所以真正能"并行"。

**一句话**：**并发是"看起来同时"，并行是"真的同时"。** 单核 CPU 上多线程只能并发（时间片轮转），多核才能并行。

## 2. 三种创建方式（03–05）

### 2.1 方式一：继承 Thread

```java
public class MyThread extends Thread {
    @Override
    public void run() {
        for (int i = 0; i < 5; i++) {
            System.out.println(getName() + " 执行: " + i);
        }
    }

    public static void main(String[] args) {
        MyThread t = new MyThread();
        t.setName("线程A");
        t.start();      // 启动线程（不是 run！）
    }
}
```

**关键**：
- **重写 `run()`**：线程要执行的代码
- **调 `start()`**：真正启动线程（**不是 `run()`**）
- `start()` 会新开一个线程执行 `run()`；直接调 `run()` 就是普通方法调用（单线程）

### 2.2 方式二：实现 Runnable（推荐）

```java
public class MyRunnable implements Runnable {
    @Override
    public void run() {
        System.out.println(Thread.currentThread().getName() + " 执行 Runnable");
    }

    public static void main(String[] args) {
        MyRunnable r = new MyRunnable();
        Thread t = new Thread(r, "线程B");    // 名字可以直接传
        t.start();
    }
}
```

**lambda 简写（最常用）：**

```java
Runnable r = () -> System.out.println("lambda 线程");
new Thread(r, "线程C").start();
```

**为什么推荐 Runnable？**
- Java 是单继承，继承 Thread 就占用了唯一的继承名额
- **Runnable 可以多个线程共享同一个实例**（这正是卖票问题的场景）

### 2.3 方式三：实现 Callable（带返回值）

```java
import java.util.concurrent.*;

public class MyCallable implements Callable<Integer> {
    @Override
    public Integer call() throws Exception {
        Thread.sleep(500);
        return 1 + 2 + 3;
    }

    public static void main(String[] args) throws Exception {
        // Callable 不能直接给 Thread，要配合 FutureTask
        FutureTask<Integer> task = new FutureTask<>(new MyCallable());
        new Thread(task).start();

        // get() 会阻塞，直到 call() 返回结果
        Integer result = task.get();
        System.out.println("结果: " + result);
    }
}
```

**实测：结果 6。**

**Callable vs Runnable：**

| | Runnable | Callable |
|---|---|---|
| 方法 | `run()` | `call()` |
| 返回值 | 无（void） | **有返回值** |
| 异常 | 不能抛受检异常 | 可以 `throws Exception` |
| 配合 | `new Thread(r)` | `FutureTask` / 线程池 |

### 2.4 三种方式对比

| 方式 | 优点 | 缺点 | 用不用 |
|---|---|---|---|
| 继承 Thread | 简单 | 占用继承名额 | ❌ 少用 |
| 实现 Runnable | 灵活、可共享 | 无返回值 | ✅ **最常用** |
| 实现 Callable | 有返回值、能抛异常 | 要配 FutureTask | ✅ 需要结果时用 |

## 3. 常用成员方法（06）

### 3.1 获取/设置线程名

```java
Thread t = new Thread(() -> {
    System.out.println("当前线程: " + Thread.currentThread().getName());
});
t.setName("我的线程");
t.start();
```

**实测：**

```
线程名: 我的线程
```

**方法**：`getName()`、`setName()`、`Thread.currentThread()`（拿到当前线程）。

### 3.2 sleep：线程休眠

```java
Thread.sleep(1000);     // 睡 1000 毫秒（1 秒）
```

**注意**：
- **`sleep` 是静态方法**，写在哪个线程里，就让哪个线程睡
- **会抛 `InterruptedException`**，要处理
- **sleep 不释放锁**（重要！和 `wait` 不同）

### 3.3 join：等待线程结束

```java
Thread t = new Thread(() -> {
    for (int i = 0; i < 3; i++) {
        System.out.println("  子线程: " + i);
        Thread.sleep(100);
    }
});

t.start();
t.join();       // 主线程在这里等，直到 t 结束
System.out.println("子线程结束，主线程继续");
```

**实测：**

```
子线程: 0
子线程: 1
子线程: 2
子线程结束，主线程继续
```

**`join` 的用途**：主线程要等子线程算完结果才能继续（比如多线程求和）。

### 3.4 interrupt：打断睡眠

```java
Thread t = new Thread(() -> {
    try {
        Thread.sleep(5000);
    } catch (InterruptedException e) {
        System.out.println("被 interrupt 打断");
        return;
    }
});
t.start();
Thread.sleep(100);
t.interrupt();      // 唤醒它（会抛 InterruptedException）
```

### 3.5 常用方法一览

| 方法 | 作用 | 注意 |
|---|---|---|
| `start()` | 启动线程 | 不要用 `run()` |
| `run()` | 线程执行体 | 直接调 = 普通方法 |
| `getName()` / `setName()` | 线程名 | |
| `Thread.currentThread()` | 当前线程 | 静态 |
| `sleep(ms)` | 休眠 | 静态、不释放锁 |
| `join()` | 等线程结束 | |
| `interrupt()` | 打断 | 唤醒 sleep/wait |
| `isAlive()` | 还活着吗 | |
| `getState()` | 线程状态 | |

## 4. 线程的优先级（07）

```java
Thread t = new Thread(() -> System.out.println("跑"));
t.setPriority(Thread.MAX_PRIORITY);    // 10
// 或
t.setPriority(Thread.MIN_PRIORITY);    // 1
// 默认
t.setPriority(Thread.NORM_PRIORITY);   // 5
```

**优先级范围**：1~10，默认 5。

**⚠️ 重要**：**Java 的优先级只是"建议"，不是"命令"。** 操作系统不一定理你，不能靠优先级保证执行顺序。

**实际意义不大**，知道有这个东西就行。

## 5. 守护线程（08）

### 5.1 什么是守护线程

**守护线程 = "陪跑"的线程。主线程结束，守护线程自动结束。**

**实测：**

```java
Thread daemon = new Thread(() -> {
    while (true) {
        Thread.sleep(200);
        System.out.println("  守护线程还在跑");
    }
});
daemon.setDaemon(true);     // 设成守护线程
daemon.start();
Thread.sleep(600);
System.out.println("主线程结束 -> 守护线程也会自动结束");
```

**输出：**

```
  守护线程还在跑
  守护线程还在跑
主线程结束 -> 守护线程也会自动结束
```

**主线程结束后，守护线程自动停止**（JVM 退出）。

### 5.2 典型用途

- **垃圾回收**（GC 线程就是守护线程）
- 日志刷新
- 心跳检测

**用户线程 vs 守护线程**：
- 用户线程（默认）：主线程结束，JVM **等用户线程跑完**才退出
- 守护线程：主线程结束，**JVM 直接退出**，守护线程被丢弃

## 6. 礼让线程（09）

### 6.1 yield：让出 CPU

```java
Thread.yield();     // 提示"我可以让出 CPU"
```

**注意**：`yield` 只是"建议"，**不是一定让**。CPU 可能马上又调度给你。

**用途**：让并发执行更"公平"一点（实际意义有限）。

### 6.2 和 sleep 的区别

| | `sleep` | `yield` |
|---|---|---|
| 是否让出 CPU | ✅ 一定让 | ⚠️ 可能让 |
| 是否进入阻塞 | ✅ 进入 TIMED_WAITING | ❌ 还是 RUNNABLE |
| 是否释放锁 | ❌ 不释放 | ❌ 不释放 |
| 什么时候回来 | 时间到就回来 | 随时可能被调度 |

## 7. 插入线程（10）

**`join()` 就是"插入线程"**：插到当前线程前面，等它跑完。

```java
Thread t = new Thread(() -> {
    for (int i = 0; i < 3; i++) {
        System.out.println("子线程: " + i);
        Thread.sleep(100);
    }
});

t.start();
t.join();       // 主线程"插入"到子线程后面，等它跑完
System.out.println("主线程继续");
```

**和第 3.3 节是同一个方法**，只是不同教材叫法不同。

**`join(超时)`**：

```java
t.join(2000);   // 最多等 2 秒，超时就不等了
```

## 8. 线程生命周期：六种状态（11、22）

### 8.1 六种状态（`Thread.State` 枚举）

| 状态 | 含义 | 什么时候 |
|---|---|---|
| **NEW** | 新建 | `new Thread()` 后、`start()` 前 |
| **RUNNABLE** | 就绪/运行 | `start()` 后（可能正在跑，也可能在等 CPU） |
| **BLOCKED** | 阻塞 | 等锁（synchronized 没抢到） |
| **WAITING** | 无限等待 | `wait()`、`join()`（没有超时） |
| **TIMED_WAITING** | 限时等待 | `sleep(ms)`、`join(ms)`、`wait(ms)` |
| **TERMINATED** | 终止 | `run()` 执行完或异常结束 |

### 8.2 实测状态变化

```java
Thread t = new Thread(() -> {
    try { Thread.sleep(200); } catch (InterruptedException e) {}
});

System.out.println("新建: " + t.getState());       // NEW
t.start();
System.out.println("启动后: " + t.getState());     // RUNNABLE 或 TIMED_WAITING
Thread.sleep(250);
System.out.println("结束后: " + t.getState());     // TERMINATED
```

**实测：**

```
新建: NEW
启动后: RUNNABLE
结束后: TERMINATED
```

### 8.3 状态转换图

```
        new Thread()
             │
             ▼
           NEW
             │ start()
             ▼
        ┌─────────┐
        │ RUNNABLE│◄──── 被唤醒 / 时间到 / 抢到锁
        └────┬────┘
             │
    ┌────────┼────────┬──────────┐
    ▼        ▼        ▼          ▼
 BLOCKED  WAITING  TIMED_   TERMINATED
（等锁）  （wait）  WAITING    （结束）
                     （sleep）
```

**关键理解**：
- **`RUNNABLE` 是唯一的"活动"状态**（包括正在跑和在等 CPU）
- **`BLOCKED` 只因为锁**
- **`WAITING` / `TIMED_WAITING` 因为主动等待**
- **`TERMINATED` 不可逆**

## 9. 一页速查表

### 创建

| 方式 | 写法 |
|---|---|
| 继承 Thread | `class X extends Thread { run() {...} }` |
| 实现 Runnable | `new Thread(() -> {...}, "名字")` |
| 实现 Callable | `new FutureTask<>(() -> 值)` + `new Thread(task)` |

### 常用方法

| 方法 | 作用 |
|---|---|
| `start()` | 启动 |
| `run()` | 线程体（不直接调） |
| `sleep(ms)` | 休眠（不释放锁） |
| `join()` | 等它结束 |
| `join(ms)` | 等最多 ms |
| `interrupt()` | 打断 |
| `getName()` / `setName()` | 名字 |
| `setDaemon(true)` | 守护线程 |
| `getState()` | 状态 |
| `Thread.currentThread()` | 当前线程 |

### 状态

| 状态 | 触发 |
|---|---|
| NEW | new 之后 |
| RUNNABLE | start 之后 |
| BLOCKED | 等 synchronized 锁 |
| WAITING | wait() / join() |
| TIMED_WAITING | sleep(ms) / join(ms) |
| TERMINATED | 结束 |

## 10. 常见错误速查

| ❌ 错法 | ✅ 对法 | 后果 |
|---|---|---|
| 调 `t.run()` 想启动线程 | `t.start()` | 变成普通方法调用，单线程 |
| `sleep` 以为会释放锁 | 用 `wait()` 才释放 | 死锁风险 |
| 靠优先级保证顺序 | 用 `join` 或同步机制 | 顺序不确定 |
| 忘记处理 `InterruptedException` | try-catch | 编译错误 |
| 守护线程里做重要持久化 | 用用户线程 | 主线程结束数据丢失 |
| 以为 `yield` 一定让出 CPU | 只是建议 | 结果不确定 |

## 记忆口诀

> **start 才启动，run 只是普通方法调用；**
> **Runnable 最常用，Callable 有返回值；**
> **sleep 不释放锁，wait 才释放；**
> **join 等它跑完，守护线程主死它也死；**
> **六种状态：NEW、RUNNABLE、BLOCKED、WAITING、TIMED_WAITING、TERMINATED。**
