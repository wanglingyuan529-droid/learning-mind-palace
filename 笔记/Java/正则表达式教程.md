# 正则表达式使用教程（Java 版）

> 用途：学习笔记 · 定位：只要"技"（怎么写、怎么用、怎么避坑），不讲"道"（NFA/DFA、自动机理论）
> 所有示例和输出都是在本机 JDK 27 上用 jshell 实测跑出来的

---

## 0. 一句话认识

正则表达式 = **一套描述文字规则的符号**，用来做四件事：

| 想干什么   | 意思              | 例子                               |
| ------ | --------------- | -------------------------------- |
| **判断** | 这段文字符不符合规则      | 判断是不是手机号                         |
| **查找** | 从一堆文字里找出符合规则的片段 | 从一段话里找出所有数字                      |
| **替换** | 把符合规则的片段换掉      | 把日期 `2024-10-19` 改成 `19/10/2024` |
| **切割** | 按规则把字符串切开       | 按逗号、空格、分号混着切                     |

**它本身不是 Java 的东西**，几乎所有语言都有，语法基本通用。你学的是"正则语法"，Java 只是提供了几个调用的方法。

---

## 1. 先看效果（三个真实场景）

```java
// ① 判断：是不是手机号
"13812345678".matches("^1[3-9]\\d{9}$");     // true
"12812345678".matches("^1[3-9]\\d{9}$");     // false（第二位不能是 2）

// ② 查找：从一段话里找出所有数字
Matcher m = Pattern.compile("\\d+").matcher("订单号 2024 金额 1280");
while (m.find()) System.out.println(m.group());
// 输出：2024
//       1280

// ③ 替换：把 年-月-日 改成 日/月/年
"2024-10-19".replaceAll("(\\d{4})-(\\d{2})-(\\d{2})", "$3/$2/$1");
// 输出：19/10/2024
```

看到这三个，你就知道正则能干什么了。下面全部是"怎么写出那个规则"。

## 2. Java 里有两个入口

### 入口 A：`String` 类自带的方法（最简单，一次性的活用它）

```java
"abc123".matches("\\d+");              // 判断（整串匹配）
"abc123".replaceAll("\\d+", "#");      // 替换全部
"abc123".replaceFirst("\\d+", "#");    // 只替换第一个
"a1b2c".split("\\d+");                 // 切割，返回 String[]
```

### 入口 B：`Pattern` + `Matcher`（复杂活、要提取内容、要反复用）

```java
import java.util.regex.*;

Pattern p = Pattern.compile("\\d+");   // ① 先编译规则
Matcher m = p.matcher("a123b456");     // ② 拿规则去匹配一个字符串
while (m.find()) {                     // ③ 反复找
    System.out.println(m.group());     //    找到的片段
}
```

**怎么选：**

| 场景 | 用哪个 |
|---|---|
| 一次性判断/替换/切分 | `String` 的方法，一行搞定 |
| 要从字符串里**提取**内容 | `Pattern` + `Matcher`（`String` 没这功能） |
| 要把同一规则**反复用很多次** | `Pattern` 预编译，别每次重新写 |

## 3. 语法速成（记住这张表就够用 90%）

### 3.1 单个字符怎么表示

| 写法 | 意思 | 例子 |
|---|---|---|
| `a` | 就是字母 a | `abc` 匹配 "abc" |
| `.` | **任意一个字符**（除了换行） | `a.c` 匹配 "abc"、"a1c" |
| `[abc]` | a 或 b 或 c 中的**一个** | `[abc]+` 匹配 "abcabc" |
| `[^abc]` | **不是** a/b/c 的任意一个 | `[^0-9]` 匹配非数字 |
| `[a-z]` | 区间：小写字母 | `[a-z]+` 匹配 "abc" |
| `[0-9]` | 区间：数字 | `[0-9]+` 匹配 "123" |
| `\d` | 数字（等价 `[0-9]`） | `\d{3}` 匹配 "123" |
| `\w` | 字母/数字/下划线 | `\w+` 匹配 "abc_123" |
| `\s` | 空白（空格、TAB、换行） | `\s+` 匹配 " " |

**大写的都是"取反"**：`\D` 非数字、`\W` 非字母数字、`\S` 非空白。

### 3.2 出现几次（量词）

| 写法 | 意思 | 例子 |
|---|---|---|
| `*` | 0 次或多次 | `ab*` 匹配 "a"、"ab"、"abbb" |
| `+` | 1 次或多次（至少一次） | `ab+` 匹配 "ab"、"abbb"，**不匹配 "a"** |
| `?` | 0 次或 1 次（可有可无） | `ab?` 匹配 "a"、"ab" |
| `{n}` | 正好 n 次 | `\d{3}` 匹配 "123"，**不匹配 "1234"** |
| `{n,}` | 至少 n 次 | `\d{3,}` 匹配 "1234" |
| `{n,m}` | n 到 m 次 | `\d{2,4}` 匹配 "12"~"1234" |

实测对比：

```
\d{3} 匹配 "123"   → true
\d{3} 匹配 "1234"  → false   ← 整串匹配，多一个字符就不行
```

### 3.3 位置（边界）

| 写法 | 意思 |
|---|---|
| `^` | 字符串开头 |
| `$` | 字符串结尾 |
| `\b` | 单词边界（字母和空格/标点交界处） |

```
^1[3-9]\d{9}$   → 必须以 1 开头、以数字结尾的完整手机号
```

**`^` 和 `$` 通常成对出现**，表示"整串必须完全符合"。不写的话可能匹配到一部分（见第 4 节）。

### 3.4 分组和"或"

| 写法 | 意思 | 例子 |
|---|---|---|
| `(abc)` | 把 abc 当成一个整体，同时**捕获**它 | 用 `m.group(1)` 取出来 |
| `(?:abc)` | 只当整体，**不捕获** | 不需要取内容时用，省内存 |
| `a\|b` | a 或 b | `cat\|dog` 匹配 "cat" 或 "dog" |

```
(\d{4})-(\d{2})-(\d{2})    → 捕获三组：年、月、日
```

## 4. Java 特有的三个坑（必须记住）

### 坑 1：正则写在 Java 字符串里，反斜杠要**双写**

```java
// 正则本身写 \d，但在 Java 字符串里必须写 \\d
"123".matches("\\d+");     // ✅ 正确
"123".matches("\d+");      // ❌ 编译错误：illegal escape character
```

**原因一句话**：Java 字符串里 `\` 本身是转义符，要表示一个真正的 `\` 就得写 `\\`。

**实用记法**：正则里凡是带 `\` 的（`\d`、`\w`、`\s`、`\.`），在 Java 里统一**多写一个**。

### 坑 2：`matches()` 是**整串**匹配，不是"包含"

```java
"123".matches("\\d+");       // true
"a123b".matches("\\d+");     // false  ← 因为整串不是纯数字
"a123b".matches(".*\\d+.*"); // true   ← 想包含，前后加 .*
```

这个坑最常见：你想判断"字符串里有没有数字"，结果用了 `matches("\\d+")`，得到 false。

**要"部分匹配/查找"就用 `find()`：**

```java
Pattern p = Pattern.compile("\\d+");
Matcher m = p.matcher("a123b456c");
while (m.find()) {
    System.out.println(m.group() + " 位置 " + m.start() + "~" + m.end());
}
// 输出：
// 123 位置 1~4
// 456 位置 5~8
```

### 坑 3：`replaceAll`、`split`、`replaceFirst` 里的参数**都是正则**

```java
"a.b".replace(".", "-");        // → a-b     （replace 是纯文本替换）
"a.b".replaceAll(".", "-");     // → ---     （. 是任意字符，三个字符全换）
"a.b.c".split(".");             // → []      （按任意字符切，结果全是空串）
"a.b.c".split("\\.");           // → [a, b, c]  （想按点切必须转义）
```

**记住：`replace` 是纯文本，`replaceAll` 是正则。** 名字少了个 `All`，性质完全不一样。

## 5. 常用场景实战（直接抄，改改就能用）

### 5.1 手机号

```java
String phone = "^1[3-9]\\d{9}$";

"13812345678".matches(phone);   // true
"12812345678".matches(phone);   // false（第二位 2 不行）
"1381234567".matches(phone);    // false（只有 10 位）
"138123456789".matches(phone);  // false（11 位多了）
"1381234567a".matches(phone);   // false（有字母）
```

拆解：`^1` 以 1 开头 → `[3-9]` 第二位 3~9 → `\d{9}` 后面 9 个数字 → `$` 结尾。

### 5.2 邮箱（简化版，够日常用）

```java
String mail = "^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\\.[A-Za-z]{2,}$";

"a@b.com".matches(mail);          // true
"a.b+c@mail.co.uk".matches(mail); // true
"a@b".matches(mail);              // false（没有后缀）
"a@@b.com".matches(mail);         // false（两个 @）
"@b.com".matches(mail);           // false（@ 前必须有内容）
```

**注意**：正则校验邮箱只能挡掉明显错误的，真正格式合规的邮箱（比如带引号的、超长的）用正则很难完全覆盖。实用原则是"正则做初筛，真正确认靠发验证邮件"。

### 5.3 日期（带边界校验）

```java
String date = "^(\\d{4})-(0[1-9]|1[0-2])-(0[1-9]|[12]\\d|3[01])$";

"2024-10-19".matches(date);   // true
"2024-13-01".matches(date);   // false（月份 13）
"2024-00-10".matches(date);   // false（月份 0）
"2024-1-1".matches(date);     // false（月份必须两位）
"2024-02-30".matches(date);   // true  ← 注意！正则不查月份天数
```

**最后一条是关键**：`2024-02-30` 能通过，因为正则只看"01~31"的范围，不知道 2 月没有 30 号。**正则管"格式"，不管"业务合法性"**——2 月 30 号这种要用 `LocalDate.parse()` 或代码判断。

### 5.4 提取数字

```java
Matcher m = Pattern.compile("\\d+").matcher("订单号 2024 金额 1280 元 数量 3 件");
while (m.find()) System.out.println(m.group());
// 输出：2024 / 1280 / 3
```

### 5.5 提取带小数的数字

```java
Matcher m = Pattern.compile("\\d+\\.?\\d*").matcher("价格 19.99 元，重量 3.5 kg，数量 10");
while (m.find()) System.out.println(m.group());
// 输出：19.99 / 3.5 / 10
```

### 5.6 替换（含分组重排）

```java
// 日期格式转换：2024-10-19 → 19/10/2024
"2024-10-19".replaceAll("(\\d{4})-(\\d{2})-(\\d{2})", "$3/$2/$1");
// → 19/10/2024

// 把手机号中间 4 位打码
"13812345678".replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1****$2");
// → 138****5678
```

`$1`、`$2` 表示"第 1 个分组、第 2 个分组的内容"。

### 5.7 提取中文

```java
"abc中文123".replaceAll("[\\u4e00-\\u9fa5]+", "X");   // → abcX123
"中文".matches("[\\u4e00-\\u9fa5]+");                  // → true
```

`\u4e00-\u9fa5` 是常用汉字的 Unicode 范围。

## 6. Matcher 的三个方法，别搞混

| 方法 | 意思 | `"123abc456"` 上的结果 |
|---|---|---|
| `matches()` | **整串**必须匹配 | `false`（含 abc） |
| `lookingAt()` | 从**开头**匹配即可 | `true`，group=`123` |
| `find()` | **任意位置**找，可反复找 | 第一次 `123`，第二次 `456` |

实测：

```java
Matcher m = Pattern.compile("\\d+").matcher("123abc456");
m.matches();     // false
m.lookingAt();   // true, group = 123
m.find();        // true, group = 456（接着上次的位置继续找）
```

**记忆**：`matches` = 全部；`lookingAt` = 只看头；`find` = 随便找。

### 6.1 分组提取

```java
Pattern p = Pattern.compile("(\\d{4})-(\\d{2})-(\\d{2})");
Matcher m = p.matcher("日期 2024-10-19 结束");

if (m.find()) {
    System.out.println(m.group(0));   // 2024-10-19（整段）
    System.out.println(m.group(1));   // 2024（第1组）
    System.out.println(m.group(2));   // 10
    System.out.println(m.group(3));   // 19
    System.out.println(m.groupCount()); // 3（一共几组）
}
```

**`group(0)` 是整个匹配到的内容**，`group(1)` 起才是括号里的。

### 6.2 命名分组（Java 7+，推荐）

数字分组多了记不住，可以起名字：

```java
Matcher m = Pattern.compile("(?<year>\\d{4})-(?<month>\\d{2})").matcher("2024-10");
if (m.find()) {
    System.out.println(m.group("year"));    // 2024
    System.out.println(m.group("month"));   // 10
}
```

写法：`(?<名字>规则)`，取的时候用 `group("名字")`。

## 7. 贪婪 vs 懒惰（最容易写出 bug 的地方）

**默认是贪婪的：能匹配多长就匹配多长。**

```java
String s = "\"x\" \"y\"";

s.replaceAll("\".*\"", "Q");    // 贪婪 → Q        （一口气吃到最后一个引号）
s.replaceAll("\".*?\"", "Q");   // 懒惰 → Q Q      （吃到最近的引号就停）
```

**在量词后面加 `?` 就是懒惰**：`.*?`、`.+?`、`??`、`{2,5}?`。

实测对照：

| 写法 | `"<a><b>"` 替换结果 | 说明 |
|---|---|---|
| `<.*>` | `X` | 贪婪，从第一个 `<` 吃到最后一个 `>` |
| `<.*?>` | `XX` | 懒惰，每次只吃到最近的 `>` |

**什么时候用哪个：**
- 要匹配"一整块"（比如整段 HTML）→ 贪婪
- 要匹配"每一个小块"（比如每个标签）→ 懒惰

## 8. 断言：只判断位置，不消耗字符

有些位置要求"前面/后面必须是什么"，但不想把它一起匹配进来。这就是断言（也叫环视）。

| 写法 | 名字 | 意思 |
|---|---|---|
| `(?=...)` | 前瞻（正） | 后面必须是 ... |
| `(?!...)` | 前瞻（负） | 后面不能是 ... |
| `(?<=...)` | 后顾（正） | 前面必须是 ... |
| `(?<!...)` | 后顾（负） | 前面不能是 ... |

**记忆技巧**：`=` 是"是"，`!` 是"不是"；`<` 表示"看前面"。

实战：

```java
// 在数字之间插逗号（只认位置，不替换数字本身）
"100 200 300".replaceAll("(?<=\\d)(?=\\d)", ",");
// → 1,0,0 2,0,0 3,0,0

// 只要"元"前面是数字，就把"元"换成"块"
"100元 300元".replaceAll("(?<=\\d)元", "块");
// → 100块 300块

// 在"元"后面加空格
"100元200元".replaceAll("(?<=元)", " ");
// → "100元 200元 "
```

**断言最常用的地方**：只改"某个东西前面的字"或"某个东西后面的字"，但不动那个东西本身。

## 9. 几个高级但很实用的招

### 9.1 反向引用：匹配"重复的内容"

```java
// (.) 捕获任意一个字符，\1 表示"跟第1组一模一样的内容"
Pattern.compile("(.)\\1").matcher("哈哈").find();     // true（两个一样的字）

"aabb".replaceAll("(.)\\1", "[$1]");                 // → [a][b]
```

用途：找连续重复的字符、检查有没有叠字、压缩重复内容。

### 9.2 替换时用代码算新值（Java 9+）

普通的 `replaceAll` 只能换成固定字符串，要"计算"就用带函数的版本：

```java
Matcher m = Pattern.compile("(\\d+)").matcher("苹果3个 梨5个");
String r = m.replaceAll(mr -> String.valueOf(Integer.parseInt(mr.group()) * 10));
// r = 苹果30个 梨50个
```

### 9.3 忽略大小写

```java
"Abc".matches("abc");                                              // false
"Abc".matches("(?i)abc");                                          // true  ← 内联写法
Pattern.compile("abc", Pattern.CASE_INSENSITIVE).matcher("Abc").matches();  // true
```

### 9.4 让 `.` 能匹配换行

`.` 默认不匹配换行：

```java
"a\nb".matches("a.b");        // false
"a\nb".matches("(?s)a.b");    // true  ← (?s) 让它匹配换行
```

### 9.5 多行模式：`^` 和 `$` 每行都算

```java
String multi = "a\nb\nc";
Pattern.compile("^.").matcher(multi).results().count();              // 1（只匹配开头）
Pattern.compile("^.", Pattern.MULTILINE).matcher(multi).results().count(); // 3（每行都算）
```

### 9.6 写复杂正则时加注释（COMMENTS 模式）

```java
String verbose = """
        (?x)                # 开启注释模式，空格和注释会被忽略
        ^                   # 开头
        (\\d{4})            # 年
        -                   # 横线
        (\\d{2})            # 月
        $                   # 结尾
        """;
"2024-10".matches(verbose);   // true
```

复杂正则写成一行会变成天书，用 `(?x)` 拆成多行加注释，以后自己看得懂。

### 9.7 复用 Matcher

同一个 Matcher 换字符串重新匹配，用 `reset()`：

```java
Matcher m = Pattern.compile("\\d+").matcher("");
for (String t : new String[]{"a11", "bb222", "ccc3333"}) {
    m.reset(t);
    if (m.find()) System.out.println(m.group());
}
// 输出：11 / 222 / 3333
```

## 10. 性能与安全（两个必须知道的）

### 10.1 要不要预编译 Pattern？

**结论：高频调用 + 复杂正则时差异明显，短正则单次调用差异很小。**

实测（同样跑 10 万次）：

| 场景 | `String.matches()` | 预编译 Pattern |
|---|---|---|
| 短正则 `\d+` | 375 ms | 368 ms（几乎无差） |
| 复杂正则（日期+字母+数字） | 497 ms | 378 ms（快约 1.3 倍） |

**怎么用：**
- 循环里反复用同一个正则 → 提前 `Pattern.compile()` 一次，别每次写字符串
- 一次性判断 → 直接用 `String.matches()`，别为优化而优化

```java
// ❌ 循环里每次都在编译
for (String s : list) {
    if (s.matches("^1[3-9]\\d{9}$")) { ... }
}

// ✅ 编译一次
Pattern PHONE = Pattern.compile("^1[3-9]\\d{9}$");
for (String s : list) {
    if (PHONE.matcher(s).matches()) { ... }
}
```

### 10.2 小心灾难性回溯（ReDoS）

有些写法会让匹配时间**指数级爆炸**，用户传个长字符串就能让程序卡死。典型是**嵌套量词**：

```java
// ❌ 危险：a+ 外面又套了一层 +，一旦匹配失败会疯狂回溯
"(a+)+b"
"(.*){10}"

// ✅ 安全：用更精确的写法
"a+b"
".{10}"
```

**避免方法：**
- 别把量词套在量词里（`(a+)+`、`(a*)*`）
- `.*` 尽量换成明确的字符类，比如 `[^,]*`、`\w+`
- 如果正则来自用户输入，限制输入长度
- 校验手机号/邮箱这类格式，尽量用精确的字符范围而不是 `.*`

## 11. 常见错误速查（照着躲）

| ❌ 错法 | ✅ 对法 | 后果 |
|---|---|---|
| `"\d+"` | `"\\d+"` | 编译错误 |
| `"a123b".matches("\\d+")` | `"...".matches(".*\\d+.*")` 或 `find()` | 明明有数字却 false |
| `str.replaceAll(".", "-")` | `str.replace(".", "-")` | 点被当通配符，全被替换 |
| `str.split(".")` | `str.split("\\.")` | 切出空数组 |
| `replaceAll("-", "$")` | `replaceAll("-", "\\$")` | 抛 IllegalArgumentException |
| `a.equals(b)` 比较匹配结果 | 用 `matches()` 返回的 boolean | — |
| `(a+)+b` | `a+b` | 灾难性回溯，可能卡死 |
| 用正则校验日期合法性 | 正则管格式，日期用 `LocalDate` | `2024-02-30` 能通过 |

实测那条 `$` 的坑：

```
"a-b".replaceAll("-", "$")
→ IllegalArgumentException: Illegal group reference: group index is missing
"a-b".replaceAll("-", "\\$")
→ a$b
```

## 12. 一页速查表

### 字符

| 写 | 含义 | 写 | 含义 |
|---|---|---|---|
| `.` | 任意字符 | `\.` | 真正的点 |
| `\d` | 数字 | `\D` | 非数字 |
| `\w` | 字母数字下划线 | `\W` | 非字母数字 |
| `\s` | 空白 | `\S` | 非空白 |
| `[abc]` | 其中一个 | `[^abc]` | 不是其中一个 |
| `[a-z]` | 区间 | `[0-9]` | 数字区间 |

### 数量

| 写 | 含义 |
|---|---|
| `*` | 0~多次 |
| `+` | 1~多次 |
| `?` | 0 或 1 次 |
| `{n}` | 正好 n 次 |
| `{n,}` | 至少 n 次 |
| `{n,m}` | n 到 m 次 |
| `*?` `+?` `??` | 懒惰版（尽量少匹配） |

### 位置与结构

| 写 | 含义 |
|---|---|
| `^` | 开头 |
| `$` | 结尾 |
| `\b` | 单词边界 |
| `(abc)` | 分组并捕获 |
| `(?:abc)` | 分组不捕获 |
| `(?<name>...)` | 命名分组 |
| `a\|b` | 或 |
| `(?=...)` | 后面必须是 |
| `(?!...)` | 后面不能是 |
| `(?<=...)` | 前面必须是 |
| `(?<!...)` | 前面不能是 |
| `(?i)` | 忽略大小写 |
| `(?s)` | 让 `.` 匹配换行 |
| `(?m)` | 多行模式 |
| `(?x)` | 注释模式 |
| `\1` | 反向引用第 1 组 |

### Java 方法

| 想要 | 写法 |
|---|---|
| 整串判断 | `str.matches(regex)` 或 `p.matcher(str).matches()` |
| 找下一个 | `m.find()` + `m.group()` |
| 取分组 | `m.group(1)` / `m.group("name")` |
| 分组数量 | `m.groupCount()` |
| 替换全部 | `str.replaceAll(regex, 替换)` |
| 替换第一个 | `str.replaceFirst(regex, 替换)` |
| 纯文本替换 | `str.replace(文本, 替换)` ← 不是正则 |
| 切割 | `str.split(regex)` |
| 预编译 | `Pattern.compile(regex)` |
| 忽略大小写编译 | `Pattern.compile(regex, Pattern.CASE_INSENSITIVE)` |

## 13. 动手练习（直接 jshell 敲）

```java
import java.util.regex.*;

// ① 判断手机号
System.out.println("13812345678".matches("^1[3-9]\\d{9}$"));

// ② 找出句子里所有数字
Matcher m = Pattern.compile("\\d+").matcher("我有 3 个苹果，5 个梨，共 8 个");
while (m.find()) System.out.println(m.group());

// ③ 把日期格式换过来
System.out.println("2024-10-19".replaceAll("(\\d{4})-(\\d{2})-(\\d{2})", "$3/$2/$1"));

// ④ 手机号打码
System.out.println("13812345678".replaceAll("(\\d{3})\\d{4}(\\d{4})", "$1****$2"));

// ⑤ 提取邮箱（从一段乱文本里）——注意在 jshell 里必须写在一行
Matcher mm = Pattern.compile("[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\\.[A-Za-z]{2,}").matcher("联系 a@b.com 或 c.d@mail.co.uk 都可以");
while (mm.find()) System.out.println("邮箱: " + mm.group());

// ⑥ 故意踩坑：看看 replaceAll 和 replace 的区别
System.out.println("a.b".replace(".", "-"));
System.out.println("a.b".replaceAll(".", "-"));
```
