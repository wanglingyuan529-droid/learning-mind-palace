## 开篇：先弄明白"集合"到底是个啥

### 0.1 为什么要有集合

数组有三个绕不过去的毛病：

| 数组的问题 | 现实后果 |
|---|---|
| **长度固定** | 建了 10 个，第 11 个就塞不进去 |
| **只能装同一种类型** | `int[]` 只能装 int，不能混装 |
| **增删很麻烦** | 中间删一个，后面全部往前挪，得自己写循环 |

**集合就是"能自动变长、能直接增删"的容器。**

```java
// 数组：装不下就完蛋
int[] arr = new int[3];
arr[3] = 1;    // ArrayIndexOutOfBoundsException

// 集合：想加多少加多少
List<Integer> list = new ArrayList<>();
list.add(1);
list.add(2);
list.add(3);
list.add(4);   // 自动变长，不用管
```

### 0.2 一句话记住集合家族

```
          Collection（单列集合：一个一个存）
          /        |         \
       List       Set       Queue
     （有顺序）  （不重复）  （排队）
        |          |          |
   ArrayList    HashSet    LinkedList
   LinkedList   TreeSet    ArrayDeque
   Vector       LinkedHashSet
```

**加餐**：还有一套 `Map`（双列集合，键值对），它**不继承 Collection**，是独立的。本节只讲左边这一脉（单列）。

# 第一部分：Collection 顶层接口（01）

## 1. Collection 是什么

**Collection 是所有"单列集合"的老祖宗**，它定义了一套"容器该有什么操作"的规矩。

你可以把 `Collection` 理解成一张**合同**：里面规定了"能加、能删、能查、能遍历"，但**没规定具体怎么实现**。

```java
import java.util.*;

Collection<String> c = new ArrayList<>();
c.add("a");
c.add("b");

c.size();          // 2
c.contains("a");   // true
c.isEmpty();       // false
System.out.println(c);   // [a, b]    ← 直接打印就是可读内容
```

**关键点**：`Collection<String> c = new ArrayList<>()` 这一行，**左边是接口、右边是实现类**。这是集合里最常用的写法——用接口接住具体对象，以后换实现只要改右边。

### 1.1 为什么用接口接住

```java
Collection<String> c = new ArrayList<>();   // 想换只需改这一处
// Collection<String> c = new HashSet<>();
```

后面的代码 `c.add(...)`、`c.size()` 全不用动。**面向接口编程，换实现零成本。**

## 2. Collection 的常用方法（所有单列集合都有）

| 方法 | 作用 | 例子 |
|---|---|---|
| `add(E e)` | 加一个元素 | `c.add("a")` |
| `remove(Object o)` | 删掉**某个值** | `c.remove("a")` |
| `contains(Object o)` | 有没有这个值 | `c.contains("a")` |
| `size()` | 有几个元素 | `c.size()` |
| `isEmpty()` | 是不是空的 | `c.isEmpty()` |
| `clear()` | 全部清空 | `c.clear()` |
| `addAll(Collection c)` | 一次加一批 | `c.addAll(other)` |
| `removeAll(Collection c)` | 删掉另一批里的 | `c.removeAll(other)` |
| `containsAll(Collection c)` | 是不是全包含 | `c.containsAll(other)` |
| `toArray()` | 转成数组 | `c.toArray()` |

**重点理解 `remove`**：`Collection` 的 `remove` 参数是**对象**（删值），而 `List` 还多了一个**按索引删**的重载。这个区别后面会专门讲，是经典坑。

## 3. 三大分支的区别（背这张表就够）

| 分支 | 有序吗 | 能重复吗 | 有索引吗 | 记忆方法 |
|---|---|---|---|---|
| **List** | ✅ 有序 | ✅ 可重复 | ✅ 有 | "列表"，像排队，位置固定 |
| **Set** | ❌ 不保证 | ❌ **不可重复** | ❌ 无 | "集合"，像袋子，不能有重样 |
| **Queue** | ✅ 有序 | ✅ 可重复 | ❌ 无 | "队列"，先来先服务 |

实测：

```java
List<String> list   = new ArrayList<>(List.of("a","b","a"));   // [a, b, a]  保留重复
Set<String>  set    = new HashSet<>(List.of("a","b","a"));      // [a, b]     去重
Collection<String> q = new ArrayDeque<>(List.of("a","b","a"));  // [a, b, a]  允许重复
```

**小白最容易混的一点**：`Set` 不是"没顺序"，而是"**不保证顺序**"——`HashSet` 打印出来看着像有顺序，但别依赖它，要保证顺序用 `LinkedHashSet`，要排序用 `TreeSet`。

## 4. 用哪个？（决策图）

```
需要一个可以重复、按位置取的东西？
    └─ 要 → List → 通常用 ArrayList

需要去重？
    └─ 要 → Set → 通常用 HashSet

需要排队/先进先出？
    └─ 要 → Queue → 通常用 ArrayDeque

需要键值对（key → value）？
    └─ 要 → Map（不属于 Collection）
```

# 第二部分：迭代器（02）

## 5. 迭代器是什么

**迭代器（Iterator）就是"一个专门帮你从头到尾走一遍集合的小工具"。**

为什么需要它？因为不同的集合内部结构不一样：
- `ArrayList` 底层是数组，可以用下标 `get(i)`
- `HashSet` 底层是哈希表，**根本没有下标**，`get(0)` 都没法写

所以需要一个**统一的方式**把任何集合从头走到尾——这就是迭代器。

## 6. 三个方法（就三个）

| 方法 | 作用 | 类比 |
|---|---|---|
| `hasNext()` | 还有没有下一个 | 问"还有吗" |
| `next()` | 拿出下一个，并前进一格 | 抽一张 |
| `remove()` | 删掉**刚刚拿出来的**那个 | 抽出来不要了 |

```java
List<String> list = new ArrayList<>(List.of("a","b","c"));

Iterator<String> it = list.iterator();
while (it.hasNext()) {
    String s = it.next();
    System.out.println(s);
}
// a
// b
// c
```

### 6.1 走到头了还 `next()` 会炸

```java
List<String> list = new ArrayList<>(List.of("a"));
Iterator<String> it = list.iterator();
it.next();      // a
it.next();      // ❌ NoSuchElementException
```

**所以标准写法永远是 `while (it.hasNext())`，先问有没有再拿。**

### 6.2 迭代器的位置指针

```
      a       b       c
      ↑
   [迭代器]  一开始停在"第一个元素前面"

next() 之后：
      a       b       c
              ↑
           [迭代器]
```

**每调一次 `next()`，指针往后走一格并返回刚跨过的那一个。**

## 7. 用迭代器删除元素（重要）

**这可能是迭代器最重要的用途**：一边遍历一边删。

```java
List<Integer> nums = new ArrayList<>(List.of(1,2,3,4,5,6));

Iterator<Integer> it = nums.iterator();
while (it.hasNext()) {
    if (it.next() % 2 == 0) {
        it.remove();      // 删掉刚刚 next() 出来的那个
    }
}
// nums = [1, 3, 5]
```

### 7.1 为什么不能直接 `list.remove()`

```java
for (Integer n : list) {
    if (n == 2) list.remove(n);   // ❌ ConcurrentModificationException
}
```

**原因（用大白话说）**：
- 迭代器内部记着一个"修订版本号"
- 你通过 `list.remove()` 改动了集合，版本号 +1
- 迭代器下次调用 `next()` 时发现"我记的版本号和集合的对不上，说明有人偷偷改了"，于是抛异常

**这叫"快速失败（fail-fast）机制"，是 Java 的保护措施**，宁可直接报错，也不让你在遍历时把数据搞乱。

### 7.1.1 注意：它不一定每次都抛（这个最坑）

**这是实测出来的，不是所有情况都会报错：**

```java
// 情况 A：不抛！看起来"正常运行"了
List<Integer> a = new ArrayList<>(List.of(1, 2, 3));
for (Integer n : a) { if (n == 2) a.remove(n); }
// 结果 [1, 3]，没抛异常

// 情况 B：抛 ConcurrentModificationException
List<Integer> b = new ArrayList<>(List.of(1, 2, 3, 4));
for (Integer n : b) { if (n == 2) b.remove(n); }
// ❌ 抛了

// 情况 C：也抛
List<Integer> c = new ArrayList<>(List.of(1, 2, 2, 3));
for (Integer n : c) { if (n == 2) c.remove(n); }
// ❌ 抛了
```

**为什么 A 不抛？**

删掉 `2` 之后，`3` 前移到索引 1。迭代器指针刚好也要走到索引 1（末尾），而 `hasNext()` 先判断"还有没有"，发现没有了，就**根本没机会执行那行检查版本号的代码**。异常没被触发。

**这就是这类 bug 最可怕的地方：** 测试时数据是 `[1,2,3]`，一切正常，上线后数据变成 `[1,2,3,4]` 就崩了。**别依赖"我试过没报错"。**

> 记住一句话：**遍历时改集合，永远用 `removeIf` / 迭代器 `remove()`，别赌。**

### 7.2 三种正确的删除方式

```java
// 方式 1：迭代器 remove（最正统）
Iterator<Integer> it = list.iterator();
while (it.hasNext()) {
    if (it.next() == 2) it.remove();
}

// 方式 2：removeIf + lambda（最简洁，推荐）
list.removeIf(n -> n == 2);

// 方式 3：倒着用普通 for（有索引的 List 才行）
for (int i = list.size() - 1; i >= 0; i--) {
    if (list.get(i) == 2) list.remove(i);
}
```

**为什么倒着删可以、正着删不行？**

```
正着删（错）：[1, 2, 3]
              i=0 → 1，不删
              i=1 → 2，删掉 → 数组变成 [1, 3]
              i=2 → 越界或跳过 3   ❌ 后面的元素前移了

倒着删（对）：[1, 2, 3]
              i=2 → 3，不删
              i=1 → 2，删掉 → [1, 3]
              i=0 → 1，不删        ✅ 前面元素不动
```

## 8. 迭代器的两个注意事项

**① 每调一次 `iterator()` 都是一个新的迭代器，从头开始**

```java
list.iterator().next();   // a
list.iterator().next();   // 还是 a！因为又新建了一个
```

**② 一个迭代器用完就废了**

走到末尾后想再遍历，得重新 `list.iterator()`，不能复用。

# 第三部分：增强 for 与 lambda（03）

## 9. 增强 for（foreach）

### 9.1 语法

```java
for (元素类型 变量名 : 集合或数组) {
    // 用变量名操作当前元素
}
```

```java
List<String> list = List.of("a", "b", "c");

for (String s : list) {
    System.out.println(s);
}
```

**比传统 for 简单在哪：**

```java
// 传统 for（要管下标）
for (int i = 0; i < list.size(); i++) {
    String s = list.get(i);
    System.out.println(s);
}

// 增强 for（不用管下标）
for (String s : list) {
    System.out.println(s);
}
```

### 9.2 增强 for 的本质

**增强 for 就是迭代器的语法糖**——编译器会把上面那段翻译成迭代器写法。

所以：
- 能用的前提是对象实现了 `Iterable` 接口（集合和数组都行）
- **遍历时不能增删**（底层是迭代器，直接删会 `ConcurrentModificationException`）

### 9.3 增强 for 的坑

```java
List<String> list = new ArrayList<>(List.of("a", "b"));

// ❌ 遍历时删元素
for (String s : list) {
    if (s.equals("a")) list.remove(s);   // ConcurrentModificationException
}

// ❌ 想通过变量改集合里的值（改不了）
for (String s : list) {
    s = "x";        // 只改了局部变量，集合没变
}

// ✅ 改对象的内部状态可以（不是换对象）
List<StringBuilder> sbList = new ArrayList<>(List.of(new StringBuilder("x")));
for (StringBuilder sb : sbList) {
    sb.append("!");     // 对象内容变了，集合里也跟着变
}
```

**记住两条**：
1. 增强 for 里**不能增删元素**
2. 增强 for 里**不能替换引用**，但可以改对象内部状态

## 10. lambda 表达式入门

### 10.1 为什么需要 lambda

以前写"一个操作"，得用匿名内部类：

```java
// 老写法：为了打印一行，写了一整坨
list.forEach(new Consumer<String>() {
    @Override
    public void accept(String s) {
        System.out.println(s);
    }
});
```

lambda 把"只有一个方法"的接口写成一行的写法：

```java
list.forEach(s -> System.out.println(s));
```

**看到没**：同样的功能，从 5 行变成 1 行。

### 10.2 语法

```
s -> System.out.println(s)
↑        ↑
参数    方法体
```

| 情形 | 写法 |
|---|---|
| 一个参数 | `s -> 语句`（括号可省） |
| 多个参数 | `(a, b) -> 语句` |
| 无参数 | `() -> 语句` |
| 表达式（自动 return） | `(a, b) -> a + b` |
| 多行代码 | `(a, b) -> { 语句; return x; }` |

### 10.3 集合里 lambda 最常用的四个

```java
List<Integer> nums = new ArrayList<>(List.of(3, 8, 1, 9, 2, 7));

// ① 遍历
nums.forEach(n -> System.out.print(n + " "));

// ② 条件删除（代替迭代器删，最推荐）
nums.removeIf(n -> n % 2 == 0);

// ③ 批量修改
nums.replaceAll(n -> n * 2);

// ④ 排序
names.sort(Comparator.comparingInt(String::length));
```

### 10.4 方法引用 `::`（lambda 的再简化）

当 lambda 体**只是在调用一个现成方法**时，可以再简化：

```java
// 完整 lambda
s -> System.out.println(s)
// 方法引用
System.out::println

// 完整 lambda
s -> s.length()
// 方法引用
String::length
```

**记忆**："`::` 就是 '照着这个样子调方法'"，看到它就当 lambda 看。

# 第四部分：List 的方法与五种遍历（04）

## 11. List 比 Collection 多了什么

**List 在 Collection 基础上，多了"索引"相关的能力**：

| 方法 | 作用 | 说明 |
|---|---|---|
| `get(int index)` | 取指定位置 | 数组的 `arr[i]` |
| `set(int index, E e)` | 改指定位置 | **返回旧值** |
| `add(int index, E e)` | 插到指定位置 | 后面全体后移 |
| `remove(int index)` | **按索引删** | 返回被删的元素 |
| `indexOf(Object o)` | 第一次出现的位置 | 没有返回 -1 |
| `lastIndexOf(Object o)` | 最后一次出现的位置 | 没有返回 -1 |
| `subList(int f, int t)` | 截取一段 | **左闭右开**，而且是视图 |

```java
List<String> l = new ArrayList<>(List.of("a", "b", "c"));

l.get(1);              // "b"
l.set(1, "B");         // 返回旧值 "b"，列表变成 [a, B, c]
l.add(1, "X");         // [a, X, B, c]
l.indexOf("B");        // 2
l.remove(0);           // 返回 "a"，列表变成 [X, B, c]
```

## 12. 五种遍历方式（全都要认识）

```java
List<String> v = List.of("w", "x", "y", "z");

// ① 有索引的普通 for
for (int i = 0; i < v.size(); i++) {
    System.out.print(v.get(i) + " ");
}

// ② 增强 for
for (String s : v) {
    System.out.print(s + " ");
}

// ③ 迭代器
Iterator<String> it = v.iterator();
while (it.hasNext()) {
    System.out.print(it.next() + " ");
}

// ④ forEach + lambda
v.forEach(s -> System.out.print(s + " "));

// ⑤ Stream
v.stream().forEach(s -> System.out.print(s + " "));
```

**五种结果完全一样，什么时候用哪个？**

| 方式 | 什么时候用 |
|---|---|
| ① 普通 for | 需要**下标**时（比如要输出"第几位"），或需要倒着遍历删元素 |
| ② 增强 for | **只读遍历**，最常用最简洁 |
| ③ 迭代器 | 遍历时要**删除**元素 |
| ④ forEach lambda | 一行搞定，配合 lambda 很自然 |
| ⑤ Stream | 要做**筛选、转换、统计**等复杂操作 |

## 13. 坑：`remove` 的两个重载

```java
List<Integer> list = new ArrayList<>(List.of(10, 20, 30));

list.remove(1);                      // 删【索引 1】→ 删掉 20，结果 [10, 30]
list.remove(Integer.valueOf(20));    // 删【值 20】
```

**为什么？** `List` 有两个方法：
- `remove(int index)` —— 按位置删
- `remove(Object o)` —— 按值删

你传 `int` 就走第一个，传 `Integer` 就走第二个。**对 `List<Integer>` 来说这个区别极其容易踩。**

## 14. 坑：`subList` 是视图不是拷贝

```java
List<String> list = new ArrayList<>(List.of("a", "b", "c"));
List<String> sub = list.subList(0, 2);

sub.set(0, "MOD");      // 改"子列表"，原列表也变了！
// list = [MOD, b, c]
```

**想要独立副本，得再包一层：**

```java
List<String> copy = new ArrayList<>(list.subList(0, 2));
```

# 第五部分：数据结构（05，简略版）

> 这一节知道"是什么、有什么特点、适合干嘛"就行，**不用会手写**。

| 结构 | 长什么样 | 特点 | 类似生活中的 |
|---|---|---|---|
| **栈 Stack** | 竖着的一摞 | **先进后出**（LIFO） | 叠盘子，最后放的先拿走 |
| **队列 Queue** | 横着排一队 | **先进先出**（FIFO） | 排队买票 |
| **数组 Array** | 一排连续的格子 | 查得快（有下标），**中间插删慢** | 电影院的连座 |
| **链表 Linked List** | 一串用绳子连起来的东西 | 头尾插删快，**随机查慢** | 寻宝游戏，每张纸条写着下一张在哪 |

## 15. 四句话总结

- **栈**：后进先出。`push` 压入、`pop` 弹出、`peek` 看栈顶
- **队列**：先进先出。`offer` 入队、`poll` 出队、`peek` 看队头
- **数组**：查快改快，**中间插入/删除要挪一片**
- **链表**：插入/删除只改两根"绳子"，但找一个元素得从头一个个走

**这就是为什么后面要学 ArrayList（基于数组）和 LinkedList（基于链表）——它们各取所长。**

# 第六部分：ArrayList 源码分析（06，简略版）

> 知道这几个结论就行，面试常问，代码不用背。

## 16. 三个结论

**① 底层就是一个数组**

```java
// 简化后的样子
public class ArrayList<E> {
    private Object[] elementData;   // 真正的数据在这
    private int size;               // 真正有几个元素（不是数组长度）
}
```

**② 默认容量是 10，但"懒加载"**

```java
new ArrayList<>();     // 此时数组是空的，第一次 add 才变成长度 10
new ArrayList<>(100);  // 直接给 100，适合知道自己要装多少的情况
```

**③ 扩容是 1.5 倍**

装满后，新建一个约 **1.5 倍**大小的数组，把老元素全拷过去。

```
10 → 15 → 22 → 33 → 49 → ...
（源码写法：oldCapacity + (oldCapacity >> 1)）
```

**实用结论**：知道大概要装多少元素，就 `new ArrayList<>(预计大小)`，能少扩容几次。

## 17. ArrayList 的性能

| 操作 | 复杂度 | 说明 |
|---|---|---|
| `get(i)` | O(1) | 直接算地址，超快 |
| `add(末尾)` | O(1) | 除非要扩容 |
| `add(中间)` | O(n) | 后面的元素全要往后挪 |
| `remove(中间)` | O(n) | 后面的元素全要往前挪 |
| `contains` | O(n) | 要挨个比 |

**一句话**：ArrayList 适合"**查得多、改得少**"。

# 第七部分：LinkedList 与迭代器源码（07，简略版）

## 18. LinkedList 的结论

**① 底层是双向链表**

```
    ┌──────┐    ┌──────┐    ┌──────┐
    │  A   │◄──►│  B   │◄──►│  C   │
    └──────┘    └──────┘    └──────┘
     每个节点都记着"前一个"和"后一个"是谁
```

**② 两头操作特别快**

```java
LinkedList<String> ll = new LinkedList<>();
ll.addFirst("a");     // 头部加
ll.addLast("c");      // 尾部加
ll.peekFirst();       // 看头部
ll.peekLast();        // 看尾部
ll.pollFirst();       // 取走头部
ll.pollLast();        // 取走尾部
```

**③ 随机访问特别慢**

`get(5000)` 得从头一个一个走到第 5000 个。

## 19. ArrayList vs LinkedList 对比（面试必问）

| 操作 | ArrayList | LinkedList | 谁赢 |
|---|---|---|---|
| `get(i)` 随机访问 | O(1) | O(n) | **ArrayList** |
| 头部插入 | O(n) | O(1) | **LinkedList** |
| 尾部插入 | O(1) | O(1) | 平 |
| 中间插入 | O(n) | O(n) | 平（找位置都要时间） |
| 占内存 | 少 | 多（每个节点要存两根指针） | **ArrayList** |

**结论：实际项目 95% 用 ArrayList。** LinkedList 主要在"当队列用"的时候出现。

## 20. 迭代器源码（一句话）

迭代器内部有个"版本号"（`modCount`）。集合每次结构变化（增/删）版本号 +1，迭代器的 `next()` 会检查版本号对不对，对不上就抛 `ConcurrentModificationException`。

**这就是第 7.1 节"为什么遍历时不能删"的底层原因。知道这个就够了。**

# 第八部分：泛型（08，重点）

## 21. 泛型是什么

**泛型 = 给集合（或类、方法）指定"只能装什么类型"。**

```java
List<String> list = new ArrayList<>();   // <String> 就是泛型
list.add("可以");
list.add(123);    // ❌ 编译错误！只能装 String
```

## 22. 没有泛型会怎样（先说危害）

```java
List raw = new ArrayList();     // 不写泛型（叫"原始类型"）
raw.add("字符串");
raw.add(123);                   // 什么都能塞

for (Object o : raw) {
    int n = (int) o;            // ❌ ClassCastException
}
```

**问题**：
1. 什么都能塞，数据混乱
2. 取出来要手动强转
3. **强转错了要等到运行期才崩**，编译期发现不了

**有了泛型**：错误在**编译期**就被拦住了。这是泛型最大的价值——**把运行期的崩溃提前到编译期**。

## 23. 泛型的三种形态

### 23.1 泛型类

```java
class Box<T> {          // <T> 是类型参数，T 只是个名字，叫 E、K、V、Any 都行
    private T value;

    void set(T v) { value = v; }
    T get() { return value; }
}

// 用的时候指定具体类型
Box<String> b1 = new Box<>();
b1.set("hello");
b1.get();               // "hello"

Box<Integer> b2 = new Box<>();
b2.set(123);
b2.get();               // 123
```

**一个类，两种类型，不用写两遍。**

### 23.2 泛型方法

```java
// 在返回值前面用 <T> 声明
static <T> List<T> makeList(T... items) {
    return new ArrayList<>(Arrays.asList(items));
}

makeList("a", "b");    // List<String>
makeList(1, 2, 3);     // List<Integer>
```

**泛型方法可以写在任何类里，和类本身是否泛型无关。**

### 23.3 泛型接口

```java
interface Repository<T> {
    void save(T t);
    T find(int id);
}

class UserRepo implements Repository<String> {    // 实现时指定具体类型
    public void save(String s) { ... }
    public String find(int id) { ... }
}
```

## 24. 泛型不能是基本类型

```java
List<Integer> ok = new ArrayList<>();   // ✅ 用包装类
List<int>     no = new ArrayList<>();   // ❌ 编译错误
```

**原因**：泛型在运行时会被"擦除"（见第 26 节），擦除掉以后就没法区分基本类型了。所以只能用包装类，靠自动装箱拆箱兜底。

## 25. 通配符 `?`（容易懵的一节）

### 25.1 先记住一条铁律：泛型"不变"

```java
List<Integer> ints = List.of(1, 2, 3);
List<Number> nums = ints;     // ❌ 编译错误！
```

**`Integer` 是 `Number` 的子类，但 `List<Integer>` 不是 `List<Number>` 的子类。**

为什么？因为如果可以：

```java
List<Integer> ints = ...;
List<Number> nums = ints;      // 假设允许
nums.add(3.14);                // 往里塞个 double
Integer i = ints.get(0);       // ❌ 取出个 double 赋给 Integer，崩了
```

**所以 Java 干脆禁止了。这叫"泛型不变性"。**

### 25.2 上界通配符 `? extends T`（能读不能写）

```java
// 这个方法的参数可以接收 List<Integer>、List<Double>、List<Long>...
static double sumAll(List<? extends Number> nums) {
    double total = 0;
    for (Number n : nums) total += n.doubleValue();
    return total;
}

sumAll(List.of(1, 2, 3));        // 6.0
sumAll(List.of(1.5, 2.5, 3.0));  // 7.0   一个方法吃两种类型
```

**规则：`? extends` 只能读，不能往里写。**

```java
List<? extends Number> list = List.of(1, 2, 3);
Number n = list.get(0);      // ✅ 能读
list.add(3.14);              // ❌ 编译错误（不知道具体是啥类型，不敢让你塞）
```

### 25.3 下界通配符 `? super T`（能写）

```java
static void addInts(List<? super Integer> list) {
    list.add(1);          // ✅ 能写
}

List<Number> nums = new ArrayList<>();
addInts(nums);            // 能接收 List<Number>、List<Object>、List<Integer>
```

**规则：`? super` 能写，但读出来只能是 `Object`。**

### 25.4 一句话记忆

> **`? extends` = 生产（给你读的）；`? super` = 消费（让你写进去的）。**
> 这都是给"写通用工具方法"用的，日常业务代码里基本遇不到，看到能认出来就行。

## 26. 泛型擦除（知道结论就行）

**泛型只存在于编译期，运行时就擦掉了。**

```java
List<String> s = new ArrayList<>();
List<Integer> i = new ArrayList<>();

s.getClass() == i.getClass();    // true！运行期根本分不出来
```

**所以你写不出这些代码：**

```java
new T()                  // ❌ 不知道 T 是什么
new T[10]                // ❌ 不能创建泛型数组
list instanceof List<String>   // ❌ 不能判断泛型
```

# 第九部分：速查与避坑

## 27. 一页速查表

### Collection 通用

| 想要 | 写法 |
|---|---|
| 加 | `c.add(x)` |
| 删值 | `c.remove(x)` |
| 有没有 | `c.contains(x)` |
| 几个 | `c.size()` |
| 空不空 | `c.isEmpty()` |
| 清空 | `c.clear()` |
| 打印 | `System.out.println(c)` |

### List 专属

| 想要 | 写法 |
|---|---|
| 取第 i 个 | `list.get(i)` |
| 改第 i 个 | `list.set(i, x)` |
| 插到第 i 位 | `list.add(i, x)` |
| 按索引删 | `list.remove(i)` |
| 按值删 | `list.remove(Integer.valueOf(i))` |
| 第一次出现 | `list.indexOf(x)` |
| 排序 | `list.sort(null)` 或 `list.sort(Comparator...)` |

### 遍历

| 场景 | 用什么 |
|---|---|
| 只读 | 增强 for |
| 要下标 | 普通 for |
| 要删除 | `removeIf` 或迭代器 |
| 要筛选/统计 | Stream |

### 泛型

| 想要 | 写法 |
|---|---|
| 固定类型 | `List<String>` |
| 写泛型类 | `class Box<T>` |
| 写泛型方法 | `static <T> T foo(T t)` |
| 接受子类型 | `List<? extends Number>` |
| 接受父类型 | `List<? super Integer>` |

## 28. 常见错误速查（照着躲）

| ❌ 错法 | ✅ 对法 | 后果 |
|---|---|---|
| 遍历时 `list.remove()` | `list.removeIf(...)` 或迭代器 `remove()` | `ConcurrentModificationException` |
| `List<int>` | `List<Integer>` | 编译错误 |
| `List<Number> = List<Integer>` | `List<? extends Number>` | 编译错误（泛型不变） |
| `list.remove(20)` 想删值 20 | `list.remove(Integer.valueOf(20))` | 删错了（按索引删） |
| 正着 for 删元素 | 倒着 for，或 removeIf | 漏删、越界 |
| 拿 `subList` 当独立副本 | `new ArrayList<>(list.subList(...))` | 改子列表原表也变 |
| `List.of(...).add(...)` | `new ArrayList<>(List.of(...))` | `UnsupportedOperationException` |
| `Arrays.asList(...).add(...)` | 同上 | `UnsupportedOperationException`（但 set 可以） |
| 增强 for 里 `s = "x"` 想改元素 | 用 `set(i, x)` 或 `replaceAll` | 改的是局部变量，白改 |
| 依赖 `HashSet` 的顺序 | 用 `LinkedHashSet` / `TreeSet` | 顺序不可控 |

import java.util.*;

// ① 用 Collection 接住 ArrayList
Collection<String> c = new ArrayList<>();

    }

## 记忆口诀

> **Collection 是老祖宗，List 有序可重复，Set 去重没索引，Queue 排队；**
> **迭代器三件套：hasNext 问、next 拿、remove 删；**
> **增强 for 是迭代器糖衣，遍历时别增删；**
> **List 有索引，get/set/add/remove 都带坑；**
> **ArrayList 数组查得快，LinkedList 链表两头快；**
> **泛型把运行期崩溃提前到编译期，extends 读 super 写。**
